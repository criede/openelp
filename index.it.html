Pacchetti di OpenELP, il proxy EchoLink open source, per Raspberry Pi OS e Debian, in due componenti — scegline uno:

  • main: build di sviluppo giornaliere dal codice sorgente più recente di questo fork, non versioni stabili.
  • release: le versioni ufficiali di OpenELP del progetto originale (0.9.3 e successive), compilate dal codice sorgente originale non modificato con le stesse impostazioni di compilazione dei pacchetti giornalieri. Ogni versione viene conservata; apt upgrade passa a ogni nuova versione del progetto originale.

Per i dettagli consulta il repository del codice sorgente.

Progetto originale (upstream) & modifiche locali

Questo è un fork sincronizzato quotidianamente di cottsay/openelp, il progetto OpenELP originale, con una pacchettizzazione locale (questo repository APT) ed eventuali ulteriori modifiche aggiunte sopra. Per vedere esattamente in cosa differisce dal progetto originale in qualsiasi momento, confronta in tempo reale su GitHub: main upstream … main di questo fork.

Avvio rapido

Esegui sul sistema di destinazione (rileva automaticamente il nome in codice e l'architettura corretti):

# Importare la chiave pubblica di firma
curl -fsSL https://criede.github.io/openelp/pubkey.gpg | \
  sudo gpg --dearmor -o /usr/share/keyrings/openelp-db9cr.gpg

# Aggiungere la sorgente del repository. Scegliere il componente:
#   main     build di sviluppo giornaliere
#   release  versioni ufficiali upstream (0.9.3 e successive)
component=release
codename=$(sed -n 's/^VERSION_CODENAME=//p' /etc/os-release | tr -d '"')
arch=$(dpkg --print-architecture)
echo "deb [signed-by=/usr/share/keyrings/openelp-db9cr.gpg arch=${arch}] https://criede.github.io/openelp ${codename} ${component}" | \
  sudo tee /etc/apt/sources.list.d/openelp-db9cr.list

sudo apt update
sudo apt install openelp

# Obbligatorio prima del primo avvio: impostare una password (e, facoltativamente,
# la porta, gli indirizzi di ascolto, la registrazione e i filtri dei nominativi).
sudo editor /etc/openelp/ELProxy.conf

# Abilitare il proxy all'avvio e avviarlo subito.
sudo systemctl enable --now openelp.service

# Controllare lo stato del servizio e seguirne il log.
systemctl status openelp.service
journalctl -u openelp.service -f

Obbligatorio: il proxy si rifiuta di avviarsi finché Password in /etc/openelp/ELProxy.conf è ancora notset. Scegli una tua password; impostala a PUBLIC solo se vuoi gestire un proxy pubblico (insieme a un RegistrationName univoco).

Se apt update segnala un errore 404 per questa sorgente, il nome in codice del tuo sistema non viene ancora compilato (vedere la tabella sotto) — modifica invece il nome in codice in /etc/apt/sources.list.d/openelp-db9cr.list con uno di quelli supportati. In seguito, un normale sudo apt upgrade acquisisce automaticamente le nuove build giornaliere (main) o le nuove versioni upstream (release) e riavvia un proxy in esecuzione.

Non abilitare entrambi i componenti contemporaneamente: apt installa sempre la versione più alta, che di solito è una build giornaliera. Per passare un'installazione esistente da main a release, cambia il componente in /etc/apt/sources.list.d/openelp-db9cr.list, esegui sudo apt update, quindi installa esplicitamente la versione release (di solito un downgrade), ad es. sudo apt install openelp=0.9.3-1~trixie.

Rete e firewall

I client EchoLink si connettono al proxy via TCP sulla Port configurata (predefinita 8100). Il proxy stesso deve essere raggiungibile da Internet sulle porte UDP 5198 e 5199 (inoltrale sul tuo router se il proxy è dietro NAT) e necessita di accesso in uscita alla porta TCP 5200 e alle porte UDP 5198/5199. Consenti solo ai tuoi client di raggiungere la porta del proxy, a meno che tu non gestisca un proxy pubblico.

Usare il proxy con SvxLink

Nella configurazione del modulo EchoLink di SvxLink (/etc/svxlink/svxlink.d/ModuleEchoLink.conf), indica il proxy e riavvia SvxLink:

PROXY_SERVER=192.0.2.10    # indirizzo dell'host OpenELP
PROXY_PORT=8100
PROXY_PASSWORD=your-password

Il client EchoLink ufficiale per PC si configura allo stesso modo in Setup → Connections → Proxy.

Applicare le modifiche alla configurazione

OpenELP legge la propria configurazione solo all'avvio. Dopo aver modificato /etc/openelp/ELProxy.conf, riavvia il servizio (questo interrompe le connessioni client attive):

sudo systemctl restart openelp.service

Le modifiche locali a /etc/openelp/ELProxy.conf vengono mantenute durante gli aggiornamenti (è un file di configurazione dpkg). Il file è leggibile solo da root, poiché contiene la password del proxy.

Installare una versione precedente

Le versioni recenti restano disponibili nel pool per un certo tempo dopo essere state sostituite (giornaliere per una settimana, settimanali per un mese, mensili per un anno — vedere «Retention» (conservazione) in UPSTREAM-SYNC.MD), quindi di solito è possibile tornare indietro da una build giornaliera difettosa. I pacchetti delle versioni upstream (componente release) non vengono mai rimossi:

apt list -a openelp   # elenca tutte le versioni ancora presenti nel repository
sudo apt install openelp=0.9.4~dev+daily20261108.12.1.g0123456789ab-1~trixie
sudo apt-mark hold openelp   # facoltativo: impedisce ad "apt upgrade" di aggiornarlo di nuovo
# sudo apt-mark unhold openelp   # più tardi, per riprendere gli aggiornamenti automatici
