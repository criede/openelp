OpenELP DB9CR -APT-pakettivarasto

⚠ Tämä sivu on käännetty automaattisesti tekoälyllä, ja se voi sisältää virheitä. Englanninkielinen versio on määräävä. (English)

Paketteja OpenELP:stä, avoimen lähdekoodin EchoLink-välityspalvelimesta (Open Source EchoLink Proxy), Raspberry Pi OS:lle ja Debianille kahtena komponenttina — valitse niistä yksi:

  • main: päivittäiset kehitysversiot tämän forkin uusimmasta lähdekoodista, eivät vakaita julkaisuja.
  • release: OpenELP:n viralliset upstream-julkaisut (0.9.3 ja uudemmat), käännetty muuttamattomasta upstream-julkaisulähdekoodista samoilla käännösasetuksilla kuin päivittäiset paketit. Jokainen julkaisu säilytetään; apt upgrade siirtyy jokaiseen uuteen upstream-julkaisuun.

Lisätietoja on lähdekoodivarastossa.

Upstream ja paikalliset muutokset

Tämä on päivittäin synkronoitu fork projektista cottsay/openelp, joka on alkuperäinen OpenELP-projekti; sen päälle on lisätty paikallinen paketointi (tämä APT-pakettivarasto) ja mahdollisesti muita muutoksia. Jos haluat nähdä milloin tahansa tarkalleen, mikä eroaa upstreamista, vertaa suoraan GitHubissa: upstream main … tämän forkin main.

Tietoturva: main-paketit hylkäävät EchoLink-verkosta tulevat paketit, jotka laukaisisivat SvxLinkin tunnettuja haavoittuvuuksia, ennen kuin ne saavuttavat tätä välityspalvelinta käyttävän SvxLink-solmun: virheellisesti muodostetut NDATA-info-/chat-paketit (CVE-2026-73152 / GHSA-2m63-p9h9-p5rf: kaatuminen, muistin sisällön paljastuminen) sekä RTCP SDES -paketit, joiden kutsumerkissä on virheellisiä merkkejä tai yli 32 merkkiä (GHSA-6w9x-486p-ggrj: TCL-komentojen injektointi, puskurin ylivuodot). Ne myös rajoittavat aikaa, jonka asiakasohjelma saa käyttää sisäänkirjautumiseen. Tämä on väliaikainen ratkaisu eikä korvaa SvxLinkin päivittämistä versioon 26.05.2 tai uudempaan. release-paketit sisältävät muuttamattoman upstream-lähdekoodin ilman näitä muutoksia; molemmat ajavat välityspalvelinta systemd-hiekkalaatikossa.

Pika-aloitus

Suorita kohdejärjestelmässä (tunnistaa oikean koodinimen/arkkitehtuurin automaattisesti):

# Tuo julkinen allekirjoitusavain
curl -fsSL https://criede.github.io/openelp/pubkey.gpg | \
  sudo gpg --dearmor -o /usr/share/keyrings/openelp-db9cr.gpg

# Lisää varastolähde. Valitse komponentti:
#   main     päivittäiset kehitysversiot
#   release  viralliset upstream-julkaisut (0.9.3 ja uudemmat)
component=release
codename=$(sed -n 's/^VERSION_CODENAME=//p' /etc/os-release | tr -d '"')
arch=$(dpkg --print-architecture)
echo "deb [signed-by=/usr/share/keyrings/openelp-db9cr.gpg arch=${arch}] https://criede.github.io/openelp ${codename} ${component}" | \
  sudo tee /etc/apt/sources.list.d/openelp-db9cr.list

sudo apt update
sudo apt install openelp

# Pakollinen ennen ensimmäistä käynnistystä: aseta salasana (ja halutessasi
# portti, sidontaosoitteet, rekisteröinti ja kutsumerkkisuodattimet).
sudo editor /etc/openelp/ELProxy.conf

# Ota välityspalvelin käyttöön käynnistyksen yhteydessä ja käynnistä se heti.
sudo systemctl enable --now openelp.service

# Tarkista palvelun tila ja seuraa sen lokia.
systemctl status openelp.service
journalctl -u openelp.service -f

Pakollista: Välityspalvelin ei suostu käynnistymään, niin kauan kuin Password tiedostossa /etc/openelp/ELProxy.conf on yhä notset. Valitse oma salasana; aseta arvoksi PUBLIC vain, jos haluat ylläpitää julkista välityspalvelinta (yhdessä yksilöllisen RegistrationName-arvon kanssa).

Jos apt update ilmoittaa tälle lähteelle virheen 404, järjestelmäsi koodinimelle ei vielä käännetä paketteja (katso alla oleva taulukko) — muuta sen sijaan tiedoston /etc/apt/sources.list.d/openelp-db9cr.list koodinimeksi jokin tuetuista. Sen jälkeen tavallinen sudo apt upgrade hakee automaattisesti uudet päivittäiset versiot (main) tai uudet upstream-julkaisut (release) ja käynnistää käynnissä olevan välityspalvelimen uudelleen.

Älä ota molempia komponentteja käyttöön samanaikaisesti: apt asentaa aina sen version, joka on korkeampi, ja se on yleensä päivittäinen versio. Jos haluat vaihtaa olemassa olevan asennuksen komponentista main komponenttiin release, vaihda komponentti tiedostossa /etc/apt/sources.list.d/openelp-db9cr.list, suorita sudo apt update ja asenna sitten julkaisuversio erikseen (yleensä versio vaihtuu vanhempaan), esim. sudo apt install openelp=0.9.3-3~deb13.

Verkko ja palomuuri

EchoLink-asiakasohjelmat yhdistävät välityspalvelimeen TCP:llä määritettyyn porttiin Port (oletus 8100). Välityspalvelimen itsensä on oltava tavoitettavissa internetistä UDP-porteissa 5198 ja 5199 (ohjaa ne edelleen reitittimessäsi, jos välityspalvelin on NAT:n takana), ja se tarvitsee lähtevän yhteyden TCP-porttiin 5200 ja UDP-portteihin 5198/5199. Salli pääsy välityspalvelimen porttiin vain omille asiakasohjelmillesi, ellet ylläpidä julkista välityspalvelinta.

Välityspalvelimen käyttö SvxLinkin kanssa

Määritä SvxLinkin EchoLink-moduulin asetuksissa (/etc/svxlink/svxlink.d/ModuleEchoLink.conf) käyttöön välityspalvelin ja käynnistä SvxLink uudelleen:

PROXY_SERVER=192.0.2.10    # OpenELP-palvelimen osoite
PROXY_PORT=8100
PROXY_PASSWORD=your-password

Virallinen EchoLink-asiakasohjelma PC:lle määritetään samalla tavalla kohdassa Setup → Connections → Proxy.

Asetusmuutosten käyttöönotto

OpenELP lukee asetuksensa vain käynnistyessään. Kun olet muokannut tiedostoa /etc/openelp/ELProxy.conf, käynnistä palvelu uudelleen (tämä katkaisee aktiiviset asiakasyhteydet):

sudo systemctl restart openelp.service

Paikalliset muutokset tiedostoon /etc/openelp/ELProxy.conf säilyvät päivityksissä (se on dpkg:n asetustiedosto). Koska tiedosto sisältää välityspalvelimen salasanan, sitä voivat lukea vain root ja ryhmä openelp, jonka oikeuksilla palvelu toimii.

Vanhemman version asentaminen

Viimeaikaiset versiot pysyvät saatavilla poolissa jonkin aikaa sen jälkeen, kun uudempi versio on korvannut ne (päivittäiset viikon, viikoittaiset kuukauden, kuukausittaiset vuoden — katso ”Retention” (säilytys) tiedostosta UPSTREAM-SYNC.MD), joten huonon päivittäisen version voi yleensä perua. Upstream-julkaisujen paketteja (release-komponentti) ei koskaan poisteta:

apt list -a openelp   # luettelee kaikki varastossa yhä olevat versiot
sudo apt install openelp=0.9.4~dev+daily20261108.12.1.g0123456789ab-1~deb13
sudo apt-mark hold openelp   # valinnainen: estää "apt upgrade" -komentoa päivittämästä sitä taas
# sudo apt-mark unhold openelp   # myöhemmin, kun haluat jatkaa automaattisia päivityksiä

Paketit

PakettiSisältö
openelpVälityspalvelimen taustaprosessi openelpd ja sen kirjasto, esimerkkiasetukset /etc/openelp/ELProxy.conf, systemd-palvelu (openelp.service, ei oteta käyttöön automaattisesti; toimii etuoikeudettomana käyttäjänä openelp systemd-hiekkalaatikossa) ja man-sivu. Käännetty järjestelmän PCRE2-kirjastoa vasten, mukana tulevalla MD5-toteutuksella (ei riippuvuutta OpenSSL:ään) ja syslog-lokituksella. Kehitysotsaketiedostoja ei ole mukana.

32-bittiset järjestelmät: armhf-paketit käännetään Raspbiania (ARMv6+VFP) vasten, joka on 32-bittisen Raspberry Pi OS:n perusta, joten ne toimivat kaikissa Raspberry Pi -malleissa, myös Pi 1:ssä, Zerossa ja Zero W:ssä, ja ne voi asentaa myös Debianin armhf-järjestelmään (molemmat on testattu). i386 (32-bittiset PC:t) käännetään vain Debian 12:lle: Debian 13 ei enää tue i386-järjestelmien asentamista. 32-bittisissä paketeissa on samat ominaisuudet kuin 64-bittisissä.
