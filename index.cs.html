APT repozitář OpenELP DB9CR

⚠ Tato stránka byla přeložena automaticky pomocí umělé inteligence a může obsahovat chyby. Závazná je anglická verze. (English)

Balíčky OpenELP, open-source proxy pro EchoLink, pro Raspberry Pi OS a Debian, ve dvou komponentách — vyber si jednu:

  • main: denní vývojová sestavení z nejnovějšího zdrojového kódu tohoto forku, nikoli stabilní vydání.
  • release: oficiální vydání OpenELP z mateřského projektu (0.9.3 a novější), sestavená z nezměněného zdrojového kódu vydání se stejným nastavením sestavení jako denní balíčky. Každé vydání je zachováno; apt upgrade přejde na každé nové vydání mateřského projektu.

Podrobnosti najdeš ve zdrojovém repozitáři.

Mateřský projekt a místní změny

Toto je denně synchronizovaný fork projektu cottsay/openelp, původního projektu OpenELP, s vlastním balíčkováním (tento APT repozitář) a případně dalšími změnami navrch. Chceš-li kdykoli přesně zjistit, čím se fork liší od mateřského projektu, porovnej je živě na GitHubu: main mateřského projektu … main tohoto forku.

Rychlý start

Spusť na cílovém systému (správné kódové jméno a architektura se zjistí automaticky):

# Import veřejného podpisového klíče
curl -fsSL https://criede.github.io/openelp/pubkey.gpg | \
  sudo gpg --dearmor -o /usr/share/keyrings/openelp-db9cr.gpg

# Přidání zdroje repozitáře. Zvol komponentu:
#   main     denní vývojová sestavení
#   release  oficiální vydání mateřského projektu (0.9.3 a novější)
component=release
codename=$(sed -n 's/^VERSION_CODENAME=//p' /etc/os-release | tr -d '"')
arch=$(dpkg --print-architecture)
echo "deb [signed-by=/usr/share/keyrings/openelp-db9cr.gpg arch=${arch}] https://criede.github.io/openelp ${codename} ${component}" | \
  sudo tee /etc/apt/sources.list.d/openelp-db9cr.list

sudo apt update
sudo apt install openelp

# Povinné před prvním spuštěním: nastav heslo (a volitelně
# port, adresy pro naslouchání, registraci a filtry volacích značek).
sudo editor /etc/openelp/ELProxy.conf

# Povolení proxy při startu systému a jeho okamžité spuštění.
sudo systemctl enable --now openelp.service

# Kontrola stavu služby a sledování jejího protokolu.
systemctl status openelp.service
journalctl -u openelp.service -f

Povinné: Proxy se odmítne spustit, dokud má Password v /etc/openelp/ELProxy.conf stále hodnotu notset. Zvol si vlastní heslo; na PUBLIC ho nastav jen tehdy, chceš-li provozovat veřejný proxy (spolu s jedinečným RegistrationName).

Pokud apt update pro tento zdroj hlásí chybu 404, pro kódové jméno tvého systému se balíčky zatím nesestavují (viz tabulka níže) — změň proto kódové jméno v /etc/apt/sources.list.d/openelp-db9cr.list na některé z podporovaných. Poté běžný sudo apt upgrade automaticky stáhne nová denní sestavení (main) nebo nová vydání mateřského projektu (release) a restartuje běžící proxy.

Nepovoluj obě komponenty současně: apt vždy nainstaluje vyšší verzi, kterou je obvykle denní sestavení. Chceš-li přepnout existující instalaci z main na release, změň komponentu v /etc/apt/sources.list.d/openelp-db9cr.list, spusť sudo apt update a poté explicitně nainstaluj verzi vydání (obvykle jde o přechod na nižší verzi), např. sudo apt install openelp=0.9.3-1~trixie.

Síť a firewall

Klienti EchoLink se k proxy připojují přes TCP na nakonfigurovaném portu Port (výchozí 8100). Samotný proxy musí být dosažitelný z internetu na portech UDP 5198 a 5199 (přesměruj je na routeru, pokud je proxy za NAT) a potřebuje odchozí přístup k portu TCP 5200 a portům UDP 5198/5199. Povol přístup k portu proxy jen svým vlastním klientům, pokud neprovozuješ veřejný proxy.

Použití proxy se SvxLink

V konfiguraci modulu EchoLink programu SvxLink (/etc/svxlink/svxlink.d/ModuleEchoLink.conf) nastav proxy a restartuj SvxLink:

PROXY_SERVER=192.0.2.10    # adresa hostitele OpenELP
PROXY_PORT=8100
PROXY_PASSWORD=your-password

Oficiální klient EchoLink pro PC se konfiguruje stejně v Setup → Connections → Proxy.

Použití změn konfigurace

OpenELP načítá svou konfiguraci jen při spuštění. Po úpravě /etc/openelp/ELProxy.conf restartuj službu (tím se přeruší aktivní spojení klientů):

sudo systemctl restart openelp.service

Místní změny v /etc/openelp/ELProxy.conf se při aktualizacích zachovají (jde o konfigurační soubor dpkg). Soubor může číst pouze root, protože obsahuje heslo proxy.

Instalace starší verze

Nedávné verze zůstávají v poolu po nahrazení novější ještě nějakou dobu dostupné (denní po dobu týdne, týdenní po dobu měsíce, měsíční po dobu roku — viz oddíl „Retention“ (uchovávání) v UPSTREAM-SYNC.MD), takže vadné denní sestavení lze obvykle vrátit zpět. Balíčky vydání mateřského projektu (komponenta release) se nikdy neodstraňují:

apt list -a openelp   # vypíše všechny verze, které jsou v repozitáři ještě k dispozici
sudo apt install openelp=0.9.4~dev+daily20261108.12.1.g0123456789ab-1~trixie
sudo apt-mark hold openelp   # volitelné: zabrání tomu, aby jej "apt upgrade" opět povýšil
# sudo apt-mark unhold openelp   # později, pro obnovení automatických aktualizací

Balíčky

BalíčekObsah
openelpDémon proxy openelpd a jeho knihovna, ukázková konfigurace /etc/openelp/ELProxy.conf, služba systemd (openelp.service, není automaticky povolena) a manuálová stránka. Sestaveno proti systémové knihovně PCRE2, s přibalenou implementací MD5 (bez závislosti na OpenSSL) a protokolováním přes syslog. Vývojové hlavičkové soubory nejsou součástí.

32bitové systémy: balíčky armhf jsou sestaveny pro Raspbian (ARMv6+VFP), základ 32bitového Raspberry Pi OS, takže běží na každém modelu Raspberry Pi včetně Pi 1, Zero a Zero W a instalují se také na Debian armhf (obojí je testováno). i386 (32bitová PC) se sestavuje pouze pro Debian 12: Debian 13 již nepodporuje instalaci systémů i386. 32bitové balíčky mají stejné funkce jako 64bitové.
