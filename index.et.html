OpenELP DB9CR APT-hoidla

⚠ See lehekülg on tõlgitud automaatselt tehisintellekti abil ja võib sisaldada vigu. Määrav on ingliskeelne versioon. (English)

OpenELP (avatud lähtekoodiga EchoLinki puhverserver, Open Source EchoLink Proxy) paketid Raspberry Pi OS-i ja Debiani jaoks kahes komponendis — vali üks:

  • main: igapäevased arendusversioonid selle forki uusimast lähtekoodist, mitte stabiilsed väljalasked.
  • release: OpenELP-i ametlikud upstream-väljalasked (0.9.3 ja uuemad), mis on ehitatud muutmata upstream-väljalaske lähtekoodist samade ehitussätetega nagu igapäevased paketid. Iga väljalase säilitatakse; apt upgrade liigub edasi igale uuele upstream-väljalaskele.

Üksikasjad leiad lähtekoodihoidlast.

Upstream ja kohalikud muudatused

See on igapäevaselt sünkroniseeritav fork projektist cottsay/openelp, mis on algne OpenELP-i projekt, millele on lisatud kohalik pakendamine (see APT-hoidla) ja võimalik, et ka muid muudatusi. Et igal ajal täpselt näha, mille poolest see upstreamist erineb, võrdle otse GitHubis: upstream main … selle forki main.

Kiirjuhend

Käivita sihtsüsteemis (tuvastab õige koodnime/arhitektuuri automaatselt):

# Impordi avalik allkirjastamisvõti
curl -fsSL https://criede.github.io/openelp/pubkey.gpg | \
  sudo gpg --dearmor -o /usr/share/keyrings/openelp-db9cr.gpg

# Lisa hoidla allikas. Vali komponent:
#   main     igapäevased arendusversioonid
#   release  ametlikud upstream-väljalasked (0.9.3 ja uuemad)
component=release
codename=$(sed -n 's/^VERSION_CODENAME=//p' /etc/os-release | tr -d '"')
arch=$(dpkg --print-architecture)
echo "deb [signed-by=/usr/share/keyrings/openelp-db9cr.gpg arch=${arch}] https://criede.github.io/openelp ${codename} ${component}" | \
  sudo tee /etc/apt/sources.list.d/openelp-db9cr.list

sudo apt update
sudo apt install openelp

# Kohustuslik enne esimest käivitamist: määra parool (ja soovi korral
# port, sidumisaadressid, registreerimine ja kutsungifiltrid).
sudo editor /etc/openelp/ELProxy.conf

# Luba puhverserveri käivitumine alglaadimisel ja käivita see kohe.
sudo systemctl enable --now openelp.service

# Kontrolli teenuse olekut ja jälgi selle logi.
systemctl status openelp.service
journalctl -u openelp.service -f

Nõutav: Puhverserver keeldub käivitumast, kuni Password failis /etc/openelp/ELProxy.conf on endiselt notset. Vali oma parool; määra selleks PUBLIC ainult siis, kui soovid pidada avalikku puhverserverit (koos unikaalse RegistrationName-iga).

Kui apt update annab selle allika kohta vea 404, siis sinu süsteemi koodnime jaoks veel pakette ei ehitata (vt allolevat tabelit) — muuda selle asemel failis /etc/apt/sources.list.d/openelp-db9cr.list koodnimi mõneks toetatud koodnimeks. Pärast seda toob tavaline sudo apt upgrade automaatselt uued igapäevased versioonid (main) või uued upstream-väljalasked (release) ja taaskäivitab töötava puhverserveri.

Ära luba mõlemat komponenti korraga: apt paigaldab alati kõrgema versiooni, milleks on tavaliselt igapäevane versioon. Olemasoleva paigalduse vahetamiseks komponendilt main komponendile release muuda komponenti failis /etc/apt/sources.list.d/openelp-db9cr.list, käivita sudo apt update ja paigalda seejärel väljalaske versioon selgesõnaliselt (tavaliselt on see versiooni alandamine), nt sudo apt install openelp=0.9.3-1~trixie.

Võrk ja tulemüür

EchoLinki kliendid ühenduvad puhverserveriga TCP kaudu seadistatud pordil Port (vaikimisi 8100). Puhverserver ise peab olema internetist kättesaadav UDP-portidel 5198 ja 5199 (suuna need ruuteris edasi, kui puhverserver asub NAT-i taga) ning vajab väljaminevat juurdepääsu TCP-pordile 5200 ja UDP-portidele 5198/5199. Luba puhverserveri pordile ligi ainult oma kliente, välja arvatud juhul, kui pead avalikku puhverserverit.

Puhverserveri kasutamine koos SvxLinkiga

Suuna SvxLinki EchoLinki mooduli konfiguratsioonis (/etc/svxlink/svxlink.d/ModuleEchoLink.conf) see puhverserverile ja taaskäivita SvxLink:

PROXY_SERVER=192.0.2.10    # OpenELP-i hosti aadress
PROXY_PORT=8100
PROXY_PASSWORD=your-password

Ametlik EchoLinki arvutiklient seadistatakse samamoodi menüüs Setup → Connections → Proxy.

Konfiguratsioonimuudatuste rakendamine

OpenELP loeb oma konfiguratsiooni ainult käivitumisel. Pärast faili /etc/openelp/ELProxy.conf muutmist taaskäivita teenus (see katkestab aktiivsed klientühendused):

sudo systemctl restart openelp.service

Kohalikud muudatused failis /etc/openelp/ELProxy.conf säilivad uuendamisel (see on dpkg konfiguratsioonifail). Faili saab lugeda ainult root, kuna see sisaldab puhverserveri parooli.

Vanema versiooni paigaldamine

Hiljutised versioonid jäävad pärast uuemaga asendamist mõneks ajaks pooli kättesaadavaks (igapäevased nädalaks, iganädalased kuuks, igakuised aastaks — vt „Retention“ (säilitamine) failis UPSTREAM-SYNC.MD), nii et halva igapäevase versiooni saab tavaliselt tagasi pöörata. Upstream-väljalasete pakette (release-komponent) ei eemaldata kunagi:

apt list -a openelp   # loetleb kõik hoidlas veel olevad versioonid
sudo apt install openelp=0.9.4~dev+daily20261108.12.1.g0123456789ab-1~trixie
sudo apt-mark hold openelp   # valikuline: takistab "apt upgrade" käsul seda uuesti uuendamast
# sudo apt-mark unhold openelp   # hiljem, automaatsete uuenduste jätkamiseks

Paketid

PakettSisu
openelpPuhverserveri deemon openelpd ja selle teek, näidiskonfiguratsioon /etc/openelp/ELProxy.conf, systemd teenus (openelp.service, ei lubata automaatselt) ja kasutusjuhendi lehekülg. Ehitatud süsteemi PCRE2 teegi vastu, kaasasoleva MD5 teostusega (ilma OpenSSL-i sõltuvuseta) ja syslogi kaudu logimisega. Arenduse päisefaile ei ole kaasas.

32-bitised süsteemid: armhf-paketid ehitatakse Raspbiani (ARMv6+VFP) vastu, mis on 32-bitise Raspberry Pi OS-i alus, nii et need töötavad kõigil Raspberry Pi mudelitel, sealhulgas Pi 1, Zero ja Zero W, ning neid saab paigaldada ka Debiani armhf-süsteemi (mõlemad on testitud). i386 (32-bitised arvutid) ehitatakse ainult Debian 12 jaoks: Debian 13 ei toeta enam i386-süsteemide paigaldamist. 32-bitistel pakettidel on samad funktsioonid nagu 64-bitistel.
