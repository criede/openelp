OpenELP DB9CR APT-arkiv

⚠ Denne siden er oversatt automatisk med kunstig intelligens og kan inneholde feil. Den engelske versjonen er gjeldende. (English)

Pakker av OpenELP, den åpne EchoLink-proxyen (Open Source EchoLink Proxy), for Raspberry Pi OS og Debian, i to komponenter — velg én:

  • main: daglige utviklingsbygg fra den nyeste kildekoden i denne forken, ikke stabile utgivelser.
  • release: de offisielle upstream-utgivelsene av OpenELP (0.9.3 og nyere), bygget fra den uendrede upstream-kildekoden for utgivelsen med de samme bygginnstillingene som de daglige pakkene. Hver utgivelse beholdes; apt upgrade går over til hver nye upstream-utgivelse.

Se kildekodearkivet for detaljer.

Upstream og lokale endringer

Dette er en daglig synkronisert fork av cottsay/openelp, det opprinnelige OpenELP-prosjektet, med lokal pakking (dette APT-arkivet) og eventuelt flere endringer lagt oppå. For når som helst å se nøyaktig hva som skiller seg fra upstream, kan du sammenligne direkte på GitHub: upstream main … denne forkens main.

Sikkerhet: main-pakkene forkaster nettverkspakker fra EchoLink-nettverket som ville utløse kjente sårbarheter i SvxLink, før de når en SvxLink-node som bruker denne proxyen: feilformede NDATA-pakker med info/chat (CVE-2026-73152 / GHSA-2m63-p9h9-p5rf: krasj, lekkasje av minneinnhold) og RTCP SDES-pakker med et kallesignal som inneholder ugyldige tegn eller mer enn 32 tegn (GHSA-6w9x-486p-ggrj: injeksjon av TCL-kommandoer, bufferoverflyt). De begrenser også hvor lang tid en klient kan bruke på å logge inn. Dette er en midlertidig løsning, ikke en erstatning for å oppdatere SvxLink til 26.05.2 eller nyere. release-pakkene inneholder uendret upstream-kildekode uten disse endringene; begge kjører proxyen i en systemd-sandkasse.

Hurtigstart

Kjør på målsystemet (finner riktig kodenavn/arkitektur automatisk):

# Importer den offentlige signeringsnøkkelen
curl -fsSL https://criede.github.io/openelp/pubkey.gpg | \
  sudo gpg --dearmor -o /usr/share/keyrings/openelp-db9cr.gpg

# Legg til arkivkilden. Velg komponent:
#   main     daglige utviklingsbygg
#   release  offisielle upstream-utgivelser (0.9.3 og nyere)
component=release
codename=$(sed -n 's/^VERSION_CODENAME=//p' /etc/os-release | tr -d '"')
arch=$(dpkg --print-architecture)
echo "deb [signed-by=/usr/share/keyrings/openelp-db9cr.gpg arch=${arch}] https://criede.github.io/openelp ${codename} ${component}" | \
  sudo tee /etc/apt/sources.list.d/openelp-db9cr.list

sudo apt update
sudo apt install openelp

# Obligatorisk før første oppstart: angi et passord (og eventuelt
# port, bindingsadresser, registrering og kallesignalfiltre).
sudo editor /etc/openelp/ELProxy.conf

# Aktiver proxyen ved oppstart og start den nå.
sudo systemctl enable --now openelp.service

# Sjekk tjenestestatus og følg loggen.
systemctl status openelp.service
journalctl -u openelp.service -f

Påkrevd: Proxyen nekter å starte så lenge Password i /etc/openelp/ELProxy.conf fortsatt er notset. Velg ditt eget passord; sett det til PUBLIC bare hvis du vil drive en offentlig proxy (sammen med et unikt RegistrationName).

Hvis apt update rapporterer 404 for denne kilden, bygges ikke systemets kodenavn ennå (se tabellen nedenfor) — endre i stedet kodenavnet i /etc/apt/sources.list.d/openelp-db9cr.list til et av de støttede. Deretter henter en vanlig sudo apt upgrade automatisk nye daglige bygg (main) eller nye upstream-utgivelser (release) og starter en kjørende proxy på nytt.

Ikke aktiver begge komponentene samtidig: apt installerer alltid den høyeste versjonen, som vanligvis er et daglig bygg. For å bytte en eksisterende installasjon fra main til release, endre komponenten i /etc/apt/sources.list.d/openelp-db9cr.list, kjør sudo apt update og installer deretter utgivelsesversjonen eksplisitt (vanligvis en nedgradering), f.eks. sudo apt install openelp=0.9.3-1~trixie.

Nettverk og brannmur

EchoLink-klienter kobler til proxyen over TCP på den konfigurerte Port (standard 8100). Selve proxyen må være nåbar fra Internett på UDP-portene 5198 og 5199 (videresend dem i ruteren hvis proxyen står bak NAT) og trenger utgående tilgang til TCP-port 5200 og UDP-portene 5198/5199. La bare dine egne klienter nå proxyporten, med mindre du driver en offentlig proxy.

Bruke proxyen med SvxLink

Pek SvxLinks konfigurasjon av EchoLink-modulen (/etc/svxlink/svxlink.d/ModuleEchoLink.conf) mot proxyen og start SvxLink på nytt:

PROXY_SERVER=192.0.2.10    # adressen til OpenELP-verten
PROXY_PORT=8100
PROXY_PASSWORD=your-password

Den offisielle EchoLink-klienten for PC konfigureres på samme måte under Setup → Connections → Proxy.

Ta i bruk konfigurasjonsendringer

OpenELP leser konfigurasjonen sin bare ved oppstart. Etter å ha redigert /etc/openelp/ELProxy.conf starter du tjenesten på nytt (dette kobler fra aktive klientforbindelser):

sudo systemctl restart openelp.service

Lokale endringer i /etc/openelp/ELProxy.conf beholdes ved oppgraderinger (det er en dpkg-konfigurasjonsfil). Siden filen inneholder proxypassordet, kan den bare leses av root og gruppen openelp som tjenesten kjører som.

Installere en eldre versjon

Nylige versjoner forblir tilgjengelige i poolen en stund etter at de er erstattet (daglig i en uke, ukentlig i en måned, månedlig i et år — se «Retention» (oppbevaring) i UPSTREAM-SYNC.MD), så et dårlig daglig bygg kan vanligvis rulles tilbake. Pakker med upstream-utgivelser (komponenten release) fjernes aldri:

apt list -a openelp   # viser alle versjoner som fortsatt finnes i arkivet
sudo apt install openelp=0.9.4~dev+daily20261108.12.1.g0123456789ab-1~trixie
sudo apt-mark hold openelp   # valgfritt: hindrer "apt upgrade" i å oppgradere den igjen
# sudo apt-mark unhold openelp   # senere, for å gjenoppta automatiske oppdateringer

Pakker

PakkeInnhold
openelpProxydemonen openelpd og biblioteket dens, eksempelkonfigurasjonen /etc/openelp/ELProxy.conf, en systemd-tjeneste (openelp.service, aktiveres ikke automatisk; kjører som den uprivilegerte brukeren openelp i en systemd-sandkasse) og manualsiden. Bygget mot systemets PCRE2-bibliotek, med den medfølgende MD5-implementasjonen (ingen avhengighet av OpenSSL) og logging via syslog. Utviklingsheaderfiler er ikke inkludert.

32-biters systemer: armhf-pakker bygges mot Raspbian (ARMv6+VFP), grunnlaget for 32-biters Raspberry Pi OS, så de kjører på alle Raspberry Pi-modeller inkludert Pi 1, Zero og Zero W, og kan også installeres på Debian armhf (begge er testet). i386 (32-biters PC-er) bygges bare for Debian 12: Debian 13 støtter ikke lenger installasjon av i386-systemer. 32-biterspakkene har de samme funksjonene som 64-biterspakkene.
