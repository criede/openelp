OpenELP DB9CR APT saugykla

⚠ Šis puslapis išverstas automatiškai naudojant dirbtinį intelektą ir gali turėti klaidų. Galiojanti yra angliška versija. (English)

OpenELP (atvirojo kodo EchoLink tarpinio serverio, Open Source EchoLink Proxy) paketai, skirti Raspberry Pi OS ir Debian, dviejuose komponentuose — pasirink vieną:

  • main: kasdieniai kūrimo versijų rinkiniai iš naujausio šios atšakos išeitinio kodo, o ne stabilios laidos.
  • release: oficialios pirminio OpenELP projekto laidos (0.9.3 ir naujesnės), sukompiliuotos iš nepakeisto pirminio projekto laidos išeitinio kodo su tais pačiais kompiliavimo nustatymais kaip ir kasdieniai paketai. Kiekviena laida išsaugoma; apt upgrade pereina prie kiekvienos naujos pirminio projekto laidos.

Daugiau informacijos rasi išeitinio kodo saugykloje.

Pirminis projektas ir vietiniai pakeitimai

Tai kasdien sinchronizuojama atšaka projekto cottsay/openelp, t. y. pirminio OpenELP projekto, su vietiniu pakavimu (šia APT saugykla) ir, galbūt, kitais papildomais pakeitimais. Jei nori bet kuriuo metu tiksliai pamatyti, kuo ji skiriasi nuo pirminio projekto, palygink tiesiogiai GitHub: upstream main … šios atšakos main.

Greita pradžia

Vykdyk tikslinėje sistemoje (tinkamas kodinis pavadinimas / architektūra nustatomi automatiškai):

# Importuok viešąjį pasirašymo raktą
curl -fsSL https://criede.github.io/openelp/pubkey.gpg | \
  sudo gpg --dearmor -o /usr/share/keyrings/openelp-db9cr.gpg

# Pridėk saugyklos šaltinį. Pasirink komponentą:
#   main     kasdieniai kūrimo versijų rinkiniai
#   release  oficialios pirminio projekto laidos (0.9.3 ir naujesnės)
component=release
codename=$(sed -n 's/^VERSION_CODENAME=//p' /etc/os-release | tr -d '"')
arch=$(dpkg --print-architecture)
echo "deb [signed-by=/usr/share/keyrings/openelp-db9cr.gpg arch=${arch}] https://criede.github.io/openelp ${codename} ${component}" | \
  sudo tee /etc/apt/sources.list.d/openelp-db9cr.list

sudo apt update
sudo apt install openelp

# Privaloma prieš pirmąjį paleidimą: nustatyk slaptažodį (ir, jei nori,
# prievadą, susiejimo adresus, registraciją ir šaukinių filtrus).
sudo editor /etc/openelp/ELProxy.conf

# Įjunk tarpinio serverio paleidimą įkrovos metu ir paleisk jį dabar.
sudo systemctl enable --now openelp.service

# Patikrink tarnybos būseną ir stebėk jos žurnalą.
systemctl status openelp.service
journalctl -u openelp.service -f

Būtina: Tarpinis serveris atsisako pasileisti, kol Password faile /etc/openelp/ELProxy.conf vis dar yra notset. Pasirink savo slaptažodį; nustatyk jį į PUBLIC tik tada, jei nori valdyti viešą tarpinį serverį (kartu su unikaliu RegistrationName).

Jei apt update šiam šaltiniui praneša klaidą 404, tavo sistemos kodiniam pavadinimui paketai dar nekompiliuojami (žr. lentelę žemiau) — vietoj to faile /etc/apt/sources.list.d/openelp-db9cr.list pakeisk kodinį pavadinimą į vieną iš palaikomų. Po to įprasta komanda sudo apt upgrade automatiškai parsiunčia naujus kasdienius rinkinius (main) arba naujas pirminio projekto laidas (release) ir iš naujo paleidžia veikiantį tarpinį serverį.

Neįjunk abiejų komponentų vienu metu: apt visada įdiegia aukštesnę versiją, kuri paprastai yra kasdienis rinkinys. Jei nori perjungti esamą diegimą iš main į release, pakeisk komponentą faile /etc/apt/sources.list.d/openelp-db9cr.list, paleisk sudo apt update ir tada aiškiai įdiek laidos versiją (paprastai tai versijos sumažinimas), pvz., sudo apt install openelp=0.9.3-1~trixie.

Tinklas ir ugniasienė

EchoLink klientai jungiasi prie tarpinio serverio per TCP sukonfigūruotu prievadu Port (numatytasis 8100). Pats tarpinis serveris turi būti pasiekiamas iš interneto UDP prievadais 5198 ir 5199 (persiųsk juos maršrutizatoriuje, jei tarpinis serveris yra už NAT) ir jam reikalinga išeinanti prieiga prie TCP prievado 5200 ir UDP prievadų 5198/5199. Leisk pasiekti tarpinio serverio prievadą tik savo klientams, nebent valdai viešą tarpinį serverį.

Tarpinio serverio naudojimas su SvxLink

SvxLink EchoLink modulio konfigūracijoje (/etc/svxlink/svxlink.d/ModuleEchoLink.conf) nurodyk tarpinį serverį ir iš naujo paleisk SvxLink:

PROXY_SERVER=192.0.2.10    # OpenELP pagrindinio kompiuterio adresas
PROXY_PORT=8100
PROXY_PASSWORD=your-password

Oficialus EchoLink kompiuterio klientas konfigūruojamas taip pat skiltyje Setup → Connections → Proxy.

Konfigūracijos pakeitimų pritaikymas

OpenELP savo konfigūraciją nuskaito tik paleidimo metu. Kai pakeiti failą /etc/openelp/ELProxy.conf, iš naujo paleisk tarnybą (tai nutraukia aktyvius klientų ryšius):

sudo systemctl restart openelp.service

Vietiniai failo /etc/openelp/ELProxy.conf pakeitimai išsaugomi atnaujinant (tai dpkg konfigūracijos failas). Failą gali skaityti tik root, nes jame yra tarpinio serverio slaptažodis.

Senesnės versijos diegimas

Naujausios versijos, jas pakeitus naujesnėmis, dar kurį laiką lieka prieinamos pool kataloge (kasdienės — savaitę, savaitinės — mėnesį, mėnesinės — metus; žr. „Retention“ (saugojimas) faile UPSTREAM-SYNC.MD), todėl blogą kasdienį rinkinį paprastai galima atšaukti. Pirminio projekto laidų paketai (release komponentas) niekada nešalinami:

apt list -a openelp   # išvardija visas saugykloje dar esančias versijas
sudo apt install openelp=0.9.4~dev+daily20261108.12.1.g0123456789ab-1~trixie
sudo apt-mark hold openelp   # nebūtina: neleidžia "apt upgrade" vėl jo atnaujinti
# sudo apt-mark unhold openelp   # vėliau, norint vėl įjungti automatinius naujinimus

Paketai

openelpTarpinio serverio tarnybinė programa openelpd ir jos biblioteka, konfigūracijos pavyzdys /etc/openelp/ELProxy.conf, systemd tarnyba (openelp.service, automatiškai neįjungiama) ir žinyno puslapis. 32 bitų sistemos: armhf paketai kompiliuojami Raspbian (ARMv6+VFP) pagrindu, kuris yra 32 bitų Raspberry Pi OS pagrindas, todėl jie veikia visuose Raspberry Pi modeliuose, įskaitant Pi 1, Zero ir Zero W, ir taip pat diegiami Debian armhf sistemoje (abu variantai išbandyti). i386 (32 bitų kompiuteriams) kompiliuojama tik Debian 12: Debian 13 nebepalaiko i386 sistemų diegimo. 32 bitų paketuose yra tos pačios funkcijos kaip ir 64 bitų paketuose.
