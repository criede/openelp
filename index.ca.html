Paquets d'OpenELP, el servidor intermediari (proxy) EchoLink de codi obert, per a Raspberry Pi OS i Debian, en dos components — tria'n un:

  • main: compilacions de desenvolupament diàries a partir del codi font més recent d'aquest fork, no versions estables.
  • release: les versions oficials d'OpenELP del projecte original (0.9.3 i posteriors), compilades a partir del codi font original sense modificar amb la mateixa configuració de compilació que els paquets diaris. Es conserven totes les versions; apt upgrade passa a cada nova versió del projecte original.

Consulta el repositori del codi font per a més detalls.

Projecte original (upstream) & canvis locals

Aquest és un fork sincronitzat diàriament de cottsay/openelp, el projecte OpenELP original, amb empaquetament local (aquest repositori APT) i possiblement altres canvis afegits a sobre. Per veure exactament en què difereix del projecte original en qualsevol moment, compara-ho en directe a GitHub: main del projecte original … main d'aquest fork.

Inici ràpid

Executa-ho al sistema de destinació (detecta automàticament el nom en clau i l'arquitectura correctes):

# Importar la clau pública de signatura
curl -fsSL https://criede.github.io/openelp/pubkey.gpg | \
  sudo gpg --dearmor -o /usr/share/keyrings/openelp-db9cr.gpg

# Afegir la font del repositori. Tria el component:
#   main     compilacions de desenvolupament diàries
#   release  versions oficials del projecte original (0.9.3 i posteriors)
component=release
codename=$(sed -n 's/^VERSION_CODENAME=//p' /etc/os-release | tr -d '"')
arch=$(dpkg --print-architecture)
echo "deb [signed-by=/usr/share/keyrings/openelp-db9cr.gpg arch=${arch}] https://criede.github.io/openelp ${codename} ${component}" | \
  sudo tee /etc/apt/sources.list.d/openelp-db9cr.list

sudo apt update
sudo apt install openelp

# Obligatori abans del primer inici: establir una contrasenya (i, opcionalment,
# el port, les adreces d'escolta, el registre i els filtres d'indicatius).
sudo editor /etc/openelp/ELProxy.conf

# Habilitar el proxy en arrencar i iniciar-lo ara.
sudo systemctl enable --now openelp.service

# Comprovar l'estat del servei i seguir-ne el registre.
systemctl status openelp.service
journalctl -u openelp.service -f

Obligatori: el proxy es nega a arrencar mentre Password a /etc/openelp/ELProxy.conf encara sigui notset. Tria una contrasenya pròpia; estableix-la a PUBLIC només si vols operar un proxy públic (juntament amb un RegistrationName únic).

Si apt update informa d'un error 404 per a aquesta font, el nom en clau del teu sistema encara no es compila (mira la taula següent) — en comptes d'això, canvia el nom en clau a /etc/apt/sources.list.d/openelp-db9cr.list per un dels compatibles. Després, un sudo apt upgrade normal obté automàticament les noves compilacions diàries (main) o les noves versions del projecte original (release) i reinicia un proxy en execució.

No habilitis tots dos components alhora: apt sempre instal·la la versió més alta, que sol ser una compilació diària. Per canviar una instal·lació existent de main a release, canvia el component a /etc/apt/sources.list.d/openelp-db9cr.list, executa sudo apt update i després instal·la explícitament la versió release (normalment un downgrade, és a dir, una versió anterior), p. ex. sudo apt install openelp=0.9.3-1~trixie.

Xarxa i tallafoc

Els clients EchoLink es connecten al proxy per TCP al Port configurat (per defecte 8100). El mateix proxy ha de ser accessible des d'Internet als ports UDP 5198 i 5199 (redirigeix-los al teu encaminador si el proxy és darrere d'un NAT) i necessita accés de sortida al port TCP 5200 i als ports UDP 5198/5199. Permet que només els teus clients accedeixin al port del proxy, tret que operis un proxy públic.

Ús del proxy amb SvxLink

A la configuració del mòdul EchoLink de SvxLink (/etc/svxlink/svxlink.d/ModuleEchoLink.conf), indica el proxy i reinicia SvxLink:

PROXY_SERVER=192.0.2.10    # adreça de l'amfitrió d'OpenELP
PROXY_PORT=8100
PROXY_PASSWORD=your-password

El client oficial d'EchoLink per a PC es configura de la mateixa manera a Setup → Connections → Proxy.

Aplicar canvis de configuració

OpenELP només llegeix la configuració en arrencar. Després d'editar /etc/openelp/ELProxy.conf, reinicia el servei (això talla les connexions de clients actives):

sudo systemctl restart openelp.service

Els canvis locals a /etc/openelp/ELProxy.conf es conserven en les actualitzacions (és un fitxer de configuració de dpkg). El fitxer només el pot llegir root, ja que conté la contrasenya del proxy.

Instal·lar una versió anterior

Les versions recents continuen disponibles al pool durant un temps després de ser substituïdes (les diàries durant una setmana, les setmanals durant un mes, les mensuals durant un any — consulta «Retention» (retenció) a UPSTREAM-SYNC.MD), de manera que normalment es pot revertir una compilació diària defectuosa. Els paquets de versions del projecte original (component release) no s'eliminen mai:

apt list -a openelp   # llista totes les versions que encara són al repositori
sudo apt install openelp=0.9.4~dev+daily20261108.12.1.g0123456789ab-1~trixie
sudo apt-mark hold openelp   # opcional: impedeix que "apt upgrade" el torni a actualitzar
# sudo apt-mark unhold openelp   # més endavant, per reprendre les actualitzacions automàtiques

Sistemes de 32 bits: els paquets armhf es compilen per a Raspbian (ARMv6+VFP), la base de Raspberry Pi OS de 32 bits, de manera que funcionen en tots els models de Raspberry Pi, inclosos el Pi 1, el Zero i el Zero W, i també s'instal·len a Debian armhf (tots dos estan provats). i386 (PC de 32 bits) només es compila per a Debian 12: Debian 13 ja no admet la instal·lació de sistemes i386. Els paquets de 32 bits ofereixen les mateixes funcionalitats que els de 64 bits.
