APT-репозиторий OpenELP DB9CR

⚠ Эта страница переведена автоматически с помощью искусственного интеллекта и может содержать ошибки. Определяющей является английская версия. (English)

Пакеты OpenELP, прокси EchoLink с открытым исходным кодом, для Raspberry Pi OS и Debian в двух компонентах — выбери один:

  • main: ежедневные сборки для разработки из самого свежего исходного кода этого форка, а не стабильные релизы.
  • release: официальные релизы OpenELP из upstream (0.9.3 и новее), собранные из неизменённого исходного кода upstream-релиза с теми же параметрами сборки, что и ежедневные пакеты. Каждый релиз сохраняется; apt upgrade переходит на каждый новый релиз upstream.

Подробности смотри в репозитории исходного кода.

Upstream и локальные изменения

Это ежедневно синхронизируемый форк cottsay/openelp, оригинального проекта OpenELP, с локальной упаковкой (этот APT-репозиторий) и, возможно, дальнейшими изменениями поверх него. Чтобы в любой момент точно увидеть, чем форк отличается от upstream, сравни актуальное состояние на GitHub: upstream main … main этого форка.

Быстрый старт

Выполни на целевой системе (нужные кодовое имя и архитектура определяются автоматически):

# Импорт открытого ключа подписи
curl -fsSL https://criede.github.io/openelp/pubkey.gpg | \
  sudo gpg --dearmor -o /usr/share/keyrings/openelp-db9cr.gpg

# Добавление источника репозитория. Выбери компонент:
#   main     ежедневные сборки для разработки
#   release  официальные релизы upstream (0.9.3 и новее)
component=release
codename=$(sed -n 's/^VERSION_CODENAME=//p' /etc/os-release | tr -d '"')
arch=$(dpkg --print-architecture)
echo "deb [signed-by=/usr/share/keyrings/openelp-db9cr.gpg arch=${arch}] https://criede.github.io/openelp ${codename} ${component}" | \
  sudo tee /etc/apt/sources.list.d/openelp-db9cr.list

sudo apt update
sudo apt install openelp

# Обязательно перед первым запуском: задай пароль (и при желании
# порт, адреса привязки, регистрацию и фильтры позывных).
sudo editor /etc/openelp/ELProxy.conf

# Включить автозапуск прокси при загрузке и запустить его сейчас.
sudo systemctl enable --now openelp.service

# Проверить состояние службы и следить за её журналом.
systemctl status openelp.service
journalctl -u openelp.service -f

Обязательно: Прокси не запустится, пока Password в /etc/openelp/ELProxy.conf всё ещё имеет значение notset. Выбери собственный пароль; устанавливай PUBLIC только если хочешь запустить публичный прокси (вместе с уникальным RegistrationName).

Если apt update сообщает об ошибке 404 для этого источника, для кодового имени твоей системы ещё нет сборок (смотри таблицу ниже) — вместо этого измени кодовое имя в /etc/apt/sources.list.d/openelp-db9cr.list на одно из поддерживаемых. После этого обычная команда sudo apt upgrade автоматически получает новые ежедневные сборки (main) или новые релизы upstream (release) и перезапускает работающий прокси.

Не включай оба компонента одновременно: apt всегда устанавливает более высокую версию, а это обычно ежедневная сборка. Чтобы перевести существующую установку с main на release, измени компонент в /etc/apt/sources.list.d/openelp-db9cr.list, выполни sudo apt update, а затем явно установи версию релиза (обычно это понижение версии), например sudo apt install openelp=0.9.3-1~trixie.

Сеть и брандмауэр

Клиенты EchoLink подключаются к прокси по TCP на настроенный Port (по умолчанию 8100). Сам прокси должен быть доступен из Интернета по UDP-портам 5198 и 5199 (перенаправь их на маршрутизаторе, если прокси находится за NAT) и нуждается в исходящем доступе к TCP-порту 5200 и UDP-портам 5198/5199. Разрешай доступ к порту прокси только своим клиентам, если ты не запускаешь публичный прокси.

Использование прокси с SvxLink

В конфигурации модуля EchoLink для SvxLink (/etc/svxlink/svxlink.d/ModuleEchoLink.conf) укажи прокси и перезапусти SvxLink:

PROXY_SERVER=192.0.2.10    # адрес хоста OpenELP
PROXY_PORT=8100
PROXY_PASSWORD=your-password

Официальный клиент EchoLink для ПК настраивается так же в разделе Setup → Connections → Proxy.

Применение изменений конфигурации

OpenELP считывает свою конфигурацию только при запуске. После редактирования /etc/openelp/ELProxy.conf перезапусти службу (при этом активные клиентские подключения разрываются):

sudo systemctl restart openelp.service

Локальные изменения в /etc/openelp/ELProxy.conf сохраняются при обновлениях (это конфигурационный файл dpkg). Файл доступен для чтения только root, поскольку содержит пароль прокси.

Установка более старой версии

Недавние версии остаются доступными в пуле (pool) ещё некоторое время после замены более новыми (ежедневные в течение недели, еженедельные в течение месяца, ежемесячные в течение года — смотри раздел «Retention» (хранение) в UPSTREAM-SYNC.MD), поэтому неудачную ежедневную сборку обычно можно откатить. Пакеты релизов upstream (компонент release) никогда не удаляются:

apt list -a openelp   # показывает все версии, которые ещё есть в репозитории
sudo apt install openelp=0.9.4~dev+daily20261108.12.1.g0123456789ab-1~trixie
sudo apt-mark hold openelp   # необязательно: не даёт "apt upgrade" снова её обновить
# sudo apt-mark unhold openelp   # позже, чтобы возобновить автоматические обновления

Кодовое имяСоответствуетАрхитектуры: main (ежедневные)Архитектуры: release
bookwormDebian 12, Raspberry Pi OS Bookworm (64/32 bit)amd64 arm64 armhf i386armhf
trixieDebian 13, Raspberry Pi OS Trixie (64/32 bit)amd64 arm64 armhfarmhf

32-битные системы: пакеты armhf собираются для Raspbian (ARMv6+VFP), основы 32-битной Raspberry Pi OS, поэтому они работают на всех моделях Raspberry Pi, включая Pi 1, Zero и Zero W, а также устанавливаются на Debian armhf (оба варианта протестированы). i386 (32-битные ПК) собирается только для Debian 12: Debian 13 больше не поддерживает установку систем i386. 32-битные пакеты содержат те же функции, что и 64-битные.
