Repozytorium APT OpenELP DB9CR

⚠ Ta strona została przetłumaczona automatycznie przy użyciu sztucznej inteligencji i może zawierać błędy. Wiążąca jest wersja angielska. (English)

Pakiety OpenELP, otwartoźródłowego proxy EchoLink, dla Raspberry Pi OS i Debiana, w dwóch komponentach — wybierz jeden:

  • main: codzienne kompilacje rozwojowe z najnowszego kodu źródłowego tego forka, a nie stabilne wydania.
  • release: oficjalne wydania OpenELP z projektu macierzystego (0.9.3 i nowsze), zbudowane z niezmienionego kodu źródłowego wydania z tymi samymi ustawieniami kompilacji co pakiety codzienne. Każde wydanie jest zachowywane; apt upgrade przechodzi na każde nowe wydanie projektu macierzystego.

Szczegóły znajdziesz w repozytorium źródłowym.

Projekt macierzysty i zmiany lokalne

To codziennie synchronizowany fork cottsay/openelp, oryginalnego projektu OpenELP, z dodanym na wierzchu własnym pakietowaniem (to repozytorium APT) i ewentualnie dalszymi zmianami. Aby w dowolnym momencie zobaczyć dokładnie, czym fork różni się od projektu macierzystego, porównaj na żywo w serwisie GitHub: main projektu macierzystego … main tego forka.

Bezpieczeństwo: pakiety main odrzucają pakiety z sieci EchoLink, które wywołałyby znane podatności SvxLink, zanim dotrą do węzła SvxLink korzystającego z tego proxy: zniekształcone pakiety NDATA typu info/chat (CVE-2026-73152 / GHSA-2m63-p9h9-p5rf: awaria, ujawnienie zawartości pamięci) oraz pakiety RTCP SDES ze znakiem wywoławczym zawierającym niedozwolone znaki lub dłuższym niż 32 znaki (GHSA-6w9x-486p-ggrj: wstrzykiwanie poleceń TCL, przepełnienia bufora). Ograniczają też czas, jaki klient może poświęcić na zalogowanie się. To rozwiązanie tymczasowe, a nie zamiennik aktualizacji SvxLink do wersji 26.05.2 lub nowszej. Pakiety release zawierają niezmieniony kod źródłowy projektu macierzystego bez tych zmian; oba warianty uruchamiają proxy w piaskownicy systemd.

Szybki start

Uruchom w systemie docelowym (właściwa nazwa kodowa i architektura są wykrywane automatycznie):

# Zaimportuj publiczny klucz podpisujący
curl -fsSL https://criede.github.io/openelp/pubkey.gpg | \
  sudo gpg --dearmor -o /usr/share/keyrings/openelp-db9cr.gpg

# Dodaj źródło repozytorium. Wybierz komponent:
#   main     codzienne kompilacje rozwojowe
#   release  oficjalne wydania projektu macierzystego (0.9.3 i nowsze)
component=release
codename=$(sed -n 's/^VERSION_CODENAME=//p' /etc/os-release | tr -d '"')
arch=$(dpkg --print-architecture)
echo "deb [signed-by=/usr/share/keyrings/openelp-db9cr.gpg arch=${arch}] https://criede.github.io/openelp ${codename} ${component}" | \
  sudo tee /etc/apt/sources.list.d/openelp-db9cr.list

sudo apt update
sudo apt install openelp

# Obowiązkowo przed pierwszym uruchomieniem: ustaw hasło (i opcjonalnie
# port, adresy nasłuchu, rejestrację oraz filtry znaków wywoławczych).
sudo editor /etc/openelp/ELProxy.conf

# Włącz proxy przy starcie systemu i uruchom je teraz.
sudo systemctl enable --now openelp.service

# Sprawdź stan usługi i śledź jej dziennik.
systemctl status openelp.service
journalctl -u openelp.service -f

Wymagane: Proxy odmawia uruchomienia, dopóki Password w /etc/openelp/ELProxy.conf ma nadal wartość notset. Wybierz własne hasło; ustaw je na PUBLIC tylko wtedy, gdy chcesz prowadzić publiczne proxy (razem z unikalną nazwą RegistrationName).

Jeśli apt update zgłasza błąd 404 dla tego źródła, pakiety dla nazwy kodowej twojego systemu nie są jeszcze budowane (zobacz tabelę poniżej) — zmień wtedy nazwę kodową w /etc/apt/sources.list.d/openelp-db9cr.list na jedną z obsługiwanych. Następnie zwykłe sudo apt upgrade automatycznie pobiera nowe kompilacje codzienne (main) lub nowe wydania projektu macierzystego (release) i restartuje działające proxy.

Nie włączaj obu komponentów jednocześnie: apt zawsze instaluje wyższą wersję, którą zwykle jest kompilacja codzienna. Aby przełączyć istniejącą instalację z main na release, zmień komponent w /etc/apt/sources.list.d/openelp-db9cr.list, uruchom sudo apt update, a następnie jawnie zainstaluj wersję wydania (zwykle jest to obniżenie wersji), np. sudo apt install openelp=0.9.3-3~deb13.

Sieć i zapora sieciowa

Klienci EchoLink łączą się z proxy przez TCP na skonfigurowanym porcie Port (domyślnie 8100). Samo proxy musi być osiągalne z Internetu na portach UDP 5198 i 5199 (przekieruj je na routerze, jeśli proxy działa za NAT) oraz potrzebuje wychodzącego dostępu do portu TCP 5200 i portów UDP 5198/5199. Zezwól na dostęp do portu proxy wyłącznie własnym klientom, chyba że prowadzisz publiczne proxy.

Korzystanie z proxy w SvxLink

W konfiguracji modułu EchoLink programu SvxLink (/etc/svxlink/svxlink.d/ModuleEchoLink.conf) wskaż proxy i zrestartuj SvxLink:

PROXY_SERVER=192.0.2.10    # adres hosta OpenELP
PROXY_PORT=8100
PROXY_PASSWORD=your-password

Oficjalny klient EchoLink na PC konfiguruje się w ten sam sposób w Setup → Connections → Proxy.

Stosowanie zmian konfiguracji

OpenELP odczytuje konfigurację tylko podczas uruchamiania. Po edycji /etc/openelp/ELProxy.conf zrestartuj usługę (przerywa to aktywne połączenia klientów):

sudo systemctl restart openelp.service

Lokalne zmiany w /etc/openelp/ELProxy.conf są zachowywane podczas aktualizacji (jest to plik konfiguracyjny dpkg). Ponieważ plik zawiera hasło proxy, może go czytać tylko root i grupa openelp, w ramach której działa usługa.

Instalacja starszej wersji

Ostatnie wersje pozostają dostępne w puli przez pewien czas po zastąpieniu przez nowsze (codzienne przez tydzień, cotygodniowe przez miesiąc, comiesięczne przez rok — zobacz sekcję „Retention” (przechowywanie) w UPSTREAM-SYNC.MD), dzięki czemu wadliwą kompilację codzienną zwykle można wycofać. Pakiety wydań projektu macierzystego (komponent release) nigdy nie są usuwane:

apt list -a openelp   # wyświetla wszystkie wersje, które są jeszcze w repozytorium
sudo apt install openelp=0.9.4~dev+daily20261108.12.1.g0123456789ab-1~deb13
sudo apt-mark hold openelp   # opcjonalnie: zapobiega ponownej aktualizacji przez "apt upgrade"
# sudo apt-mark unhold openelp   # później, aby wznowić automatyczne aktualizacje
