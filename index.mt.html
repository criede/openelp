Repożitorju APT OpenELP DB9CR

⚠ Din il-paġna ġiet tradotta awtomatikament bl-intelliġenza artifiċjali u tista’ jkun fiha żbalji. Il-verżjoni bl-Ingliż hija dik awtorevoli. (English)

Pakketti ta' OpenELP, l-EchoLink Proxy b'sors miftuħ, għal Raspberry Pi OS u Debian, f'żewġ komponenti — agħżel wieħed:

  • main: verżjonijiet ta' żvilupp ta' kuljum mill-aħħar sors ta' dan il-fork, mhux rilaxxi stabbli.
  • release: ir-rilaxxi uffiċjali upstream ta' OpenELP (0.9.3 u aktar ġodda), mibnija mis-sors mhux mibdul tar-rilaxx upstream bl-istess settings tal-bini bħall-pakketti ta' kuljum. Kull rilaxx jinżamm; apt upgrade jgħaddi għal kull rilaxx upstream ġdid.

Ara r-repożitorju tas-sors għad-dettalji.

Upstream u bidliet lokali

Dan huwa fork, sinkronizzat kuljum, ta' cottsay/openelp, il-proġett oriġinali OpenELP, b'ippakkjar lokali (dan ir-repożitorju APT) u possibbilment bidliet oħra miżjuda fuqu. Biex tara eżattament x'inhu differenti mill-upstream fi kwalunkwe ħin, qabbel live fuq GitHub: upstream main … main ta' dan il-fork.

Sigurtà: il-pakketti main jwaqqgħu pakketti min-netwerk EchoLink li jqanqlu vulnerabbiltajiet magħrufa ta' SvxLink qabel ma jilħqu node SvxLink li juża dan il-proxy: pakketti NDATA ta' informazzjoni/chat malformati (CVE-2026-73152 / GHSA-2m63-p9h9-p5rf: crash, żvelar tal-memorja) u pakketti RTCP SDES b'callsign li fih karattri invalidi jew aktar minn 32 karattru (GHSA-6w9x-486p-ggrj: injezzjoni ta' kmandi TCL, buffer overflows). Jillimitaw ukoll il-ħin li klijent jista' jieħu biex jidħol. Din hija soluzzjoni temporanja, mhux sostitut għall-aġġornament ta' SvxLink għal 26.05.2 jew aktar ġdid. Il-pakketti release fihom sors upstream mhux mibdul mingħajr dawn il-bidliet; it-tnejn iħaddmu l-proxy f'sandbox ta' systemd.

Bidu malajr

Ħaddem fuq is-sistema fil-mira (l-isem tal-kodiċi/l-arkitettura t-tajba jinstabu awtomatikament):

# Importa ċ-ċavetta pubblika tal-iffirmar
curl -fsSL https://criede.github.io/openelp/pubkey.gpg | \
  sudo gpg --dearmor -o /usr/share/keyrings/openelp-db9cr.gpg

# Żid is-sors tar-repożitorju. Agħżel il-komponent:
#   main     verżjonijiet ta' żvilupp ta' kuljum
#   release  rilaxxi uffiċjali upstream (0.9.3 u aktar ġodda)
component=release
codename=$(sed -n 's/^VERSION_CODENAME=//p' /etc/os-release | tr -d '"')
arch=$(dpkg --print-architecture)
echo "deb [signed-by=/usr/share/keyrings/openelp-db9cr.gpg arch=${arch}] https://criede.github.io/openelp ${codename} ${component}" | \
  sudo tee /etc/apt/sources.list.d/openelp-db9cr.list

sudo apt update
sudo apt install openelp

# Obbligatorju qabel l-ewwel bidu: issettja password (u jekk trid
# il-port, l-indirizzi tal-bind, ir-reġistrazzjoni u l-filtri tal-callsign).
sudo editor /etc/openelp/ELProxy.conf

# Attiva l-proxy mal-bidu tas-sistema u ibdih issa.
sudo systemctl enable --now openelp.service

# Iċċekkja l-istat tas-servizz u segwi l-log tiegħu.
systemctl status openelp.service
journalctl -u openelp.service -f

Meħtieġ: Il-proxy jirrifjuta li jibda sakemm Password f'/etc/openelp/ELProxy.conf għadu notset. Agħżel password tiegħek; issettjaha għal PUBLIC biss jekk trid tħaddem proxy pubbliku (flimkien ma' RegistrationName uniku).

Jekk apt update jirrapporta 404 għal dan is-sors, l-isem tal-kodiċi tas-sistema tiegħek għadu ma nbniex (ara t-tabella hawn taħt) — minflok, editja l-isem tal-kodiċi f'/etc/apt/sources.list.d/openelp-db9cr.list għal wieħed minn dawk appoġġjati. Wara dan, sudo apt upgrade regolari jieħu awtomatikament il-verżjonijiet ġodda ta' kuljum (main) jew ir-rilaxxi upstream ġodda (release) u jerġa' jibda proxy li jkun qed jaħdem.

Tattivax iż-żewġ komponenti fl-istess ħin: apt dejjem jinstalla liema verżjoni hija l-ogħla, li normalment hija verżjoni ta' kuljum. Biex taqleb installazzjoni eżistenti minn main għal release, ibdel il-komponent f'/etc/apt/sources.list.d/openelp-db9cr.list, ħaddem sudo apt update, imbagħad installa espliċitament il-verżjoni tar-rilaxx (normalment downgrade), eż. sudo apt install openelp=0.9.3-1~trixie.

Netwerk u firewall

Il-klijenti EchoLink jikkonnettjaw mal-proxy permezz ta' TCP fuq il-Port ikkonfigurat (default 8100). Il-proxy innifsu għandu jkun aċċessibbli mill-Internet fuq il-portijiet UDP 5198 u 5199 (għaddihom fuq ir-router tiegħek jekk il-proxy ikun wara NAT) u jeħtieġ aċċess ħiereġ għall-port TCP 5200 u l-portijiet UDP 5198/5199. Ħalli biss il-klijenti tiegħek jilħqu l-port tal-proxy sakemm ma tħaddimx proxy pubbliku.

Kif tuża l-proxy ma' SvxLink

Fil-konfigurazzjoni tal-modulu EchoLink ta' SvxLink (/etc/svxlink/svxlink.d/ModuleEchoLink.conf), ipponta lejn il-proxy u erġa' ibda SvxLink:

PROXY_SERVER=192.0.2.10    # indirizz tal-host OpenELP
PROXY_PORT=8100
PROXY_PASSWORD=your-password

Il-klijent uffiċjali EchoLink għall-PC jiġi kkonfigurat bl-istess mod taħt Setup → Connections → Proxy.

Kif tapplika bidliet fil-konfigurazzjoni

OpenELP jaqra l-konfigurazzjoni tiegħu biss meta jibda. Wara li teditja /etc/openelp/ELProxy.conf, erġa' ibda s-servizz (dan jaqta' l-konnessjonijiet attivi tal-klijenti):

sudo systemctl restart openelp.service

Il-bidliet lokali f'/etc/openelp/ELProxy.conf jinżammu waqt l-aġġornamenti (huwa fajl ta' konfigurazzjoni ta' dpkg). Peress li fih il-password tal-proxy, il-fajl jista' jinqara biss minn root u mill-grupp openelp li bih jaħdem is-servizz.

Installazzjoni ta' verżjoni eqdem

Il-verżjonijiet riċenti jibqgħu disponibbli fil-pool għal xi żmien wara li jiġu sostitwiti (dawk ta' kuljum għal ġimgħa, dawk ta' kull ġimgħa għal xahar, dawk ta' kull xahar għal sena — ara "Retention" (żamma) f' UPSTREAM-SYNC.MD), għalhekk verżjoni ħażina ta' kuljum normalment tista' titreġġa' lura. Il-pakketti tar-rilaxxi upstream (komponent release) qatt ma jitneħħew:

apt list -a openelp   # jelenka kull verżjoni li għadha fir-repożitorju
sudo apt install openelp=0.9.4~dev+daily20261108.12.1.g0123456789ab-1~trixie
sudo apt-mark hold openelp   # fakultattiv: iwaqqaf lil "apt upgrade" milli jerġa' jaġġornah
# sudo apt-mark unhold openelp   # aktar tard, biex jerġgħu jibdew l-aġġornamenti awtomatiċi
