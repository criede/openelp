OpenELP DB9CR APT-pakkasafn

⚠ Þessi síða var þýdd sjálfvirkt með gervigreind og getur innihaldið villur. Enska útgáfan gildir. (English)

Pakkar af OpenELP, EchoLink-milliþjóninum með opnum frumkóða (Open Source EchoLink Proxy), fyrir Raspberry Pi OS og Debian, í tveimur hlutum — veldu einn:

  • main: daglegar þróunarsmíðar úr nýjasta frumkóða þessarar kvíslar, ekki stöðugar útgáfur.
  • release: opinberar útgáfur OpenELP-upprunaverkefnisins (0.9.3 og nýrri), smíðaðar úr óbreyttum frumkóða útgáfunnar frá upprunaverkefninu með sömu smíðastillingum og daglegu pakkarnir. Allar útgáfur eru varðveittar; apt upgrade færist yfir í hverja nýja útgáfu upprunaverkefnisins.

Sjá frumkóðasafnið fyrir nánari upplýsingar.

Upprunaverkefni og staðbundnar breytingar

Þetta er daglega samstillt kvísl af cottsay/openelp, upprunalega OpenELP-verkefninu, með staðbundinni pökkun (þessu APT-pakkasafni) og hugsanlega frekari breytingum ofan á. Til að sjá nákvæmlega hvað er frábrugðið upprunaverkefninu hverju sinni geturðu borið saman í rauntíma á GitHub: upstream main … main í þessari kvísl.

Fljótleg byrjun

Keyrðu á markkerfinu (rétt kóðaheiti/högun er greind sjálfkrafa):

# Flyttu inn opinbera undirritunarlykilinn
curl -fsSL https://criede.github.io/openelp/pubkey.gpg | \
  sudo gpg --dearmor -o /usr/share/keyrings/openelp-db9cr.gpg

# Bættu pakkasafninu við sem uppsprettu. Veldu hluta (component):
#   main     daglegar þróunarsmíðar
#   release  opinberar útgáfur upprunaverkefnisins (0.9.3 og nýrri)
component=release
codename=$(sed -n 's/^VERSION_CODENAME=//p' /etc/os-release | tr -d '"')
arch=$(dpkg --print-architecture)
echo "deb [signed-by=/usr/share/keyrings/openelp-db9cr.gpg arch=${arch}] https://criede.github.io/openelp ${codename} ${component}" | \
  sudo tee /etc/apt/sources.list.d/openelp-db9cr.list

sudo apt update
sudo apt install openelp

# Skylda fyrir fyrstu ræsingu: settu lykilorð (og eftir atvikum
# gátt, bindivistföng, skráningu og kallmerkjasíur).
sudo editor /etc/openelp/ELProxy.conf

# Virkjaðu milliþjóninn við ræsingu kerfisins og ræstu hann núna.
sudo systemctl enable --now openelp.service

# Athugaðu stöðu þjónustunnar og fylgstu með annálnum hennar.
systemctl status openelp.service
journalctl -u openelp.service -f

Nauðsynlegt: Milliþjónninn neitar að ræsa á meðan Password í /etc/openelp/ELProxy.conf er enn notset. Veldu þitt eigið lykilorð; stilltu það á PUBLIC aðeins ef þú vilt reka opinberan milliþjón (ásamt einstöku RegistrationName).

Ef apt update tilkynnir 404 fyrir þessa uppsprettu er kóðaheiti kerfisins þíns ekki enn smíðað (sjá töfluna hér að neðan) — breyttu þá kóðaheitinu í /etc/apt/sources.list.d/openelp-db9cr.list í eitt af þeim sem eru studd. Eftir það sækir venjulegt sudo apt upgrade sjálfkrafa nýjar daglegar smíðar (main) eða nýjar útgáfur upprunaverkefnisins (release) og endurræsir milliþjón sem er í gangi.

Ekki virkja báða hlutana samtímis: apt setur alltaf upp þá útgáfu sem er hærri, sem er yfirleitt dagleg smíð. Til að skipta fyrirliggjandi uppsetningu úr main yfir í release skaltu breyta hlutanum í /etc/apt/sources.list.d/openelp-db9cr.list, keyra sudo apt update og setja síðan útgáfuna upp sérstaklega (yfirleitt niðurfærsla), t.d. sudo apt install openelp=0.9.3-1~trixie.

Netkerfi og eldveggur

EchoLink-biðlarar tengjast milliþjóninum yfir TCP á stilltri Port (sjálfgefið 8100). Milliþjónninn sjálfur verður að vera aðgengilegur af netinu á UDP-gáttum 5198 og 5199 (áframsendu þær í beininum ef milliþjónninn er á bak við NAT) og þarf útleiðaraðgang að TCP-gátt 5200 og UDP-gáttum 5198/5199. Leyfðu aðeins þínum eigin biðlurum að ná í gátt milliþjónsins nema þú rekir opinberan milliþjón.

Notkun milliþjónsins með SvxLink

Í stillingum EchoLink-einingar SvxLink (/etc/svxlink/svxlink.d/ModuleEchoLink.conf) skaltu vísa á milliþjóninn og endurræsa SvxLink:

PROXY_SERVER=192.0.2.10    # vistfang OpenELP-hýsilsins
PROXY_PORT=8100
PROXY_PASSWORD=your-password

Opinberi EchoLink-biðlarinn fyrir PC er stilltur á sama hátt undir Setup → Connections → Proxy.

Stillingabreytingar teknar í notkun

OpenELP les stillingar sínar aðeins við ræsingu. Eftir að þú hefur breytt /etc/openelp/ELProxy.conf skaltu endurræsa þjónustuna (það rýfur virkar tengingar biðlara):

sudo systemctl restart openelp.service

Staðbundnar breytingar á /etc/openelp/ELProxy.conf haldast við uppfærslur (þetta er dpkg-stillingaskrá). Aðeins root getur lesið skrána, þar sem hún inniheldur lykilorð milliþjónsins.

Uppsetning eldri útgáfu

Nýlegar útgáfur eru áfram aðgengilegar í pool um tíma eftir að nýrri útgáfa hefur leyst þær af hólmi (daglegar í viku, vikulegar í mánuð, mánaðarlegar í ár — sjá „Retention“ (varðveisla) í UPSTREAM-SYNC.MD), svo yfirleitt er hægt að snúa slæmri daglegri smíð til baka. Pakkar með útgáfum upprunaverkefnisins (hlutinn release) eru aldrei fjarlægðir:

apt list -a openelp   # listar allar útgáfur sem enn eru í pakkasafninu
sudo apt install openelp=0.9.4~dev+daily20261108.12.1.g0123456789ab-1~trixie
sudo apt-mark hold openelp   # valfrjálst: kemur í veg fyrir að "apt upgrade" uppfæri hann aftur
# sudo apt-mark unhold openelp   # síðar, til að hefja sjálfvirkar uppfærslur á ný

32 bita kerfi: armhf-pakkar eru smíðaðir gegn Raspbian (ARMv6+VFP), grunni 32 bita Raspberry Pi OS, svo þeir keyra á öllum gerðum Raspberry Pi, þar á meðal Pi 1, Zero og Zero W, og er einnig hægt að setja þá upp á Debian armhf (hvort tveggja er prófað). i386 (32 bita PC-tölvur) er aðeins smíðað fyrir Debian 12: Debian 13 styður ekki lengur uppsetningu i386-kerfa. 32 bita pakkarnir hafa sömu eiginleika og 64 bita pakkarnir.
