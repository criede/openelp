Depozitul APT OpenELP DB9CR

Pachete OpenELP, EchoLink Proxy open source, pentru Raspberry Pi OS și Debian, în două componente — alege una:

  • main: build-uri zilnice de dezvoltare din cea mai recentă sursă a acestui fork, nu versiuni stabile.
  • release: versiunile oficiale upstream ale OpenELP (0.9.3 și mai noi), compilate din sursa nemodificată a versiunii upstream cu aceleași setări de compilare ca pachetele zilnice. Fiecare versiune este păstrată; apt upgrade trece la fiecare nouă versiune upstream.

Pentru detalii, consultă depozitul de cod sursă.

Upstream și modificări locale

Acesta este un fork sincronizat zilnic al cottsay/openelp, proiectul original OpenELP, cu împachetare locală (acest depozit APT) și eventual alte modificări adăugate peste. Pentru a vedea exact ce diferă față de upstream în orice moment, compară live pe GitHub: upstream main … main al acestui fork.

Securitate: pachetele main elimină pachetele din rețeaua EchoLink care ar declanșa vulnerabilități cunoscute ale SvxLink înainte ca acestea să ajungă la un nod SvxLink care folosește acest proxy: pachete NDATA de informații/chat malformate (CVE-2026-73152 / GHSA-2m63-p9h9-p5rf: blocare, divulgare de memorie) și pachete RTCP SDES cu un indicativ care conține caractere nevalide sau mai mult de 32 de caractere (GHSA-6w9x-486p-ggrj: injecție de comenzi TCL, depășiri de buffer). De asemenea, limitează timpul pe care un client îl poate folosi pentru autentificare. Aceasta este o soluție temporară, nu un înlocuitor pentru actualizarea SvxLink la 26.05.2 sau mai nou. Pachetele release conțin sursa upstream nemodificată, fără aceste modificări; ambele rulează proxy-ul într-un sandbox systemd.

Pornire rapidă

Rulează pe sistemul țintă (numele de cod/arhitectura corectă sunt detectate automat):

# Importă cheia publică de semnare
curl -fsSL https://criede.github.io/openelp/pubkey.gpg | \
  sudo gpg --dearmor -o /usr/share/keyrings/openelp-db9cr.gpg

# Adaugă sursa depozitului. Alege componenta:
#   main     build-uri zilnice de dezvoltare
#   release  versiuni oficiale upstream (0.9.3 și mai noi)
component=release
codename=$(sed -n 's/^VERSION_CODENAME=//p' /etc/os-release | tr -d '"')
arch=$(dpkg --print-architecture)
echo "deb [signed-by=/usr/share/keyrings/openelp-db9cr.gpg arch=${arch}] https://criede.github.io/openelp ${codename} ${component}" | \
  sudo tee /etc/apt/sources.list.d/openelp-db9cr.list

sudo apt update
sudo apt install openelp

# Obligatoriu înainte de prima pornire: setează o parolă (și opțional
# portul, adresele de ascultare, înregistrarea și filtrele de indicative).
sudo editor /etc/openelp/ELProxy.conf

# Activează proxy-ul la pornirea sistemului și pornește-l acum.
sudo systemctl enable --now openelp.service

# Verifică starea serviciului și urmărește jurnalul acestuia.
systemctl status openelp.service
journalctl -u openelp.service -f

Obligatoriu: Proxy-ul refuză să pornească cât timp Password din /etc/openelp/ELProxy.conf este încă notset. Alege o parolă proprie; seteaz-o la PUBLIC doar dacă vrei să rulezi un proxy public (împreună cu un RegistrationName unic).

Dacă apt update raportează 404 pentru această sursă, numele de cod al sistemului tău nu este încă compilat (vezi tabelul de mai jos) — în schimb, modifică numele de cod din /etc/apt/sources.list.d/openelp-db9cr.list într-unul dintre cele suportate. Ulterior, un sudo apt upgrade obișnuit preia automat noile build-uri zilnice (main) sau noile versiuni upstream (release) și repornește un proxy aflat în funcțiune.

Nu activa ambele componente în același timp: apt instalează întotdeauna versiunea mai mare, care de obicei este un build zilnic. Pentru a trece o instalare existentă de la main la release, schimbă componenta în /etc/apt/sources.list.d/openelp-db9cr.list, rulează sudo apt update, apoi instalează explicit versiunea release (de obicei un downgrade), de ex. sudo apt install openelp=0.9.3-1~trixie.

Rețea și firewall

Clienții EchoLink se conectează la proxy prin TCP pe Port-ul configurat (implicit 8100). Proxy-ul însuși trebuie să fie accesibil din Internet pe porturile UDP 5198 și 5199 (redirecționează-le pe router dacă proxy-ul se află în spatele unui NAT) și are nevoie de acces de ieșire la portul TCP 5200 și la porturile UDP 5198/5199. Permite accesul la portul proxy-ului doar clienților proprii, cu excepția cazului în care rulezi un proxy public.

Utilizarea proxy-ului cu SvxLink

În configurația modulului EchoLink al SvxLink (/etc/svxlink/svxlink.d/ModuleEchoLink.conf), indică proxy-ul și repornește SvxLink:

PROXY_SERVER=192.0.2.10    # adresa gazdei OpenELP
PROXY_PORT=8100
PROXY_PASSWORD=your-password

Clientul oficial EchoLink pentru PC se configurează la fel în Setup → Connections → Proxy.

Aplicarea modificărilor de configurare

OpenELP își citește configurația doar la pornire. După editarea /etc/openelp/ELProxy.conf, repornește serviciul (acest lucru întrerupe conexiunile active ale clienților):

sudo systemctl restart openelp.service

Modificările locale din /etc/openelp/ELProxy.conf sunt păstrate la actualizări (este un fișier de configurare dpkg). Deoarece conține parola proxy-ului, fișierul poate fi citit doar de root și de grupul openelp sub care rulează serviciul.

Instalarea unei versiuni mai vechi

Versiunile recente rămân disponibile în pool o perioadă după ce au fost înlocuite (cele zilnice timp de o săptămână, cele săptămânale timp de o lună, cele lunare timp de un an — consultă „Retention” (păstrare) în UPSTREAM-SYNC.MD), astfel încât un build zilnic defect poate fi de obicei anulat. Pachetele versiunilor upstream (componenta release) nu sunt eliminate niciodată:

apt list -a openelp   # listează toate versiunile încă prezente în depozit
sudo apt install openelp=0.9.4~dev+daily20261108.12.1.g0123456789ab-1~trixie
sudo apt-mark hold openelp   # opțional: împiedică "apt upgrade" să îl actualizeze din nou
# sudo apt-mark unhold openelp   # mai târziu, pentru a relua actualizările automate
