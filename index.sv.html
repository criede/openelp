OpenELP DB9CR APT-förråd

⚠ Den här sidan har översatts automatiskt med artificiell intelligens och kan innehålla fel. Den engelska versionen gäller. (English)

Paket av OpenELP, den öppna EchoLink-proxyn (Open Source EchoLink Proxy), för Raspberry Pi OS och Debian, i två komponenter — välj en:

  • main: dagliga utvecklingsbyggen från den senaste källkoden i denna fork, inte stabila utgåvor.
  • release: de officiella upstream-utgåvorna av OpenELP (0.9.3 och nyare), byggda från den oförändrade upstream-källkoden för utgåvan med samma bygginställningar som de dagliga paketen. Varje utgåva behålls; apt upgrade går över till varje ny upstream-utgåva.

Se källkodsförrådet för detaljer.

Upstream och lokala ändringar

Detta är en dagligen synkroniserad fork av cottsay/openelp, det ursprungliga OpenELP-projektet, med lokal paketering (detta APT-förråd) och eventuellt ytterligare ändringar ovanpå. För att när som helst se exakt vad som skiljer sig från upstream kan du jämföra live på GitHub: upstream main … denna forks main.

Snabbstart

Kör på målsystemet (identifierar automatiskt rätt kodnamn/arkitektur):

# Importera den publika signeringsnyckeln
curl -fsSL https://criede.github.io/openelp/pubkey.gpg | \
  sudo gpg --dearmor -o /usr/share/keyrings/openelp-db9cr.gpg

# Lägg till förrådskällan. Välj komponent:
#   main     dagliga utvecklingsbyggen
#   release  officiella upstream-utgåvor (0.9.3 och nyare)
component=release
codename=$(sed -n 's/^VERSION_CODENAME=//p' /etc/os-release | tr -d '"')
arch=$(dpkg --print-architecture)
echo "deb [signed-by=/usr/share/keyrings/openelp-db9cr.gpg arch=${arch}] https://criede.github.io/openelp ${codename} ${component}" | \
  sudo tee /etc/apt/sources.list.d/openelp-db9cr.list

sudo apt update
sudo apt install openelp

# Obligatoriskt före första start: ange ett lösenord (och eventuellt
# port, bindningsadresser, registrering och anropssignalsfilter).
sudo editor /etc/openelp/ELProxy.conf

# Aktivera proxyn vid uppstart och starta den nu.
sudo systemctl enable --now openelp.service

# Kontrollera tjänstens status och följ dess logg.
systemctl status openelp.service
journalctl -u openelp.service -f

Krävs: Proxyn vägrar starta så länge Password i /etc/openelp/ELProxy.conf fortfarande är notset. Välj ett eget lösenord; sätt det till PUBLIC endast om du vill driva en publik proxy (tillsammans med ett unikt RegistrationName).

Om apt update rapporterar 404 för den här källan byggs ditt systems kodnamn ännu inte (se tabellen nedan) — ändra i stället kodnamnet i /etc/apt/sources.list.d/openelp-db9cr.list till ett av de som stöds. Därefter hämtar en vanlig sudo apt upgrade automatiskt nya dagliga byggen (main) eller nya upstream-utgåvor (release) och startar om en proxy som körs.

Aktivera inte båda komponenterna samtidigt: apt installerar alltid den version som är högst, vilket oftast är ett dagligt bygge. För att byta en befintlig installation från main till release, ändra komponenten i /etc/apt/sources.list.d/openelp-db9cr.list, kör sudo apt update och installera sedan utgåveversionen uttryckligen (oftast en nedgradering), t.ex. sudo apt install openelp=0.9.3-1~trixie.

Nätverk och brandvägg

EchoLink-klienter ansluter till proxyn via TCP på den konfigurerade Port (standard 8100). Själva proxyn måste vara nåbar från internet på UDP-portarna 5198 och 5199 (vidarebefordra dem i din router om proxyn står bakom NAT) och behöver utgående åtkomst till TCP-port 5200 och UDP-portarna 5198/5199. Låt endast dina egna klienter nå proxyporten, såvida du inte driver en publik proxy.

Använda proxyn med SvxLink

Peka SvxLinks konfiguration för EchoLink-modulen (/etc/svxlink/svxlink.d/ModuleEchoLink.conf) mot proxyn och starta om SvxLink:

PROXY_SERVER=192.0.2.10    # adress till OpenELP-värden
PROXY_PORT=8100
PROXY_PASSWORD=your-password

Den officiella EchoLink-klienten för pc konfigureras på samma sätt under Setup → Connections → Proxy.

Tillämpa konfigurationsändringar

OpenELP läser sin konfiguration endast vid start. Efter att ha redigerat /etc/openelp/ELProxy.conf startar du om tjänsten (detta kopplar bort aktiva klientanslutningar):

sudo systemctl restart openelp.service

Lokala ändringar i /etc/openelp/ELProxy.conf behålls vid uppgraderingar (det är en dpkg-konfigurationsfil). Filen kan bara läsas av root, eftersom den innehåller proxyns lösenord.

Installera en äldre version

Nyliga versioner finns kvar i poolen en tid efter att de har ersatts (dagligen i en vecka, veckovis i en månad, månadsvis i ett år — se ”Retention” (lagringstid) i UPSTREAM-SYNC.MD), så ett dåligt dagligt bygge kan oftast rullas tillbaka. Paket med upstream-utgåvor (komponenten release) tas aldrig bort:

apt list -a openelp   # listar alla versioner som fortfarande finns i förrådet
sudo apt install openelp=0.9.4~dev+daily20261108.12.1.g0123456789ab-1~trixie
sudo apt-mark hold openelp   # valfritt: hindrar "apt upgrade" från att uppgradera den igen
# sudo apt-mark unhold openelp   # senare, för att återuppta automatiska uppdateringar
