Pacotes do OpenELP, o proxy EchoLink de código aberto, para Raspberry Pi OS e Debian, em dois componentes — escolhe um:

  • main: compilações de desenvolvimento diárias a partir do código-fonte mais recente deste fork, não versões estáveis.
  • release: as versões oficiais do OpenELP do projeto original (0.9.3 e posteriores), compiladas a partir do código-fonte original não modificado com as mesmas definições de compilação dos pacotes diários. Todas as versões são mantidas; apt upgrade passa para cada nova versão do projeto original.

Consulta o repositório do código-fonte para mais detalhes.

Projeto original (upstream) & alterações locais

Este é um fork sincronizado diariamente de cottsay/openelp, o projeto OpenELP original, com empacotamento local (este repositório APT) e possivelmente outras alterações adicionadas por cima. Para ver exatamente o que difere do projeto original em qualquer momento, compara em tempo real no GitHub: main do projeto original … main deste fork.

Início rápido

Executa no sistema de destino (deteta automaticamente o nome de código e a arquitetura corretos):

# Importar a chave pública de assinatura
curl -fsSL https://criede.github.io/openelp/pubkey.gpg | \
  sudo gpg --dearmor -o /usr/share/keyrings/openelp-db9cr.gpg

# Adicionar a fonte do repositório. Escolhe o componente:
#   main     compilações de desenvolvimento diárias
#   release  versões oficiais do projeto original (0.9.3 e posteriores)
component=release
codename=$(sed -n 's/^VERSION_CODENAME=//p' /etc/os-release | tr -d '"')
arch=$(dpkg --print-architecture)
echo "deb [signed-by=/usr/share/keyrings/openelp-db9cr.gpg arch=${arch}] https://criede.github.io/openelp ${codename} ${component}" | \
  sudo tee /etc/apt/sources.list.d/openelp-db9cr.list

sudo apt update
sudo apt install openelp

# Obrigatório antes do primeiro arranque: definir uma palavra-passe (e, opcionalmente,
# a porta, os endereços de escuta, o registo e os filtros de indicativos).
sudo editor /etc/openelp/ELProxy.conf

# Ativar o proxy no arranque e iniciá-lo agora.
sudo systemctl enable --now openelp.service

# Verificar o estado do serviço e acompanhar o seu registo.
systemctl status openelp.service
journalctl -u openelp.service -f

Obrigatório: o proxy recusa-se a arrancar enquanto Password em /etc/openelp/ELProxy.conf for ainda notset. Escolhe uma palavra-passe tua; define-a como PUBLIC apenas se quiseres operar um proxy público (juntamente com um RegistrationName único).

Se apt update indicar um erro 404 para esta fonte, o nome de código do teu sistema ainda não é compilado (vê a tabela abaixo) — em vez disso, altera o nome de código em /etc/apt/sources.list.d/openelp-db9cr.list para um dos suportados. Depois disso, um sudo apt upgrade normal obtém automaticamente as novas compilações diárias (main) ou as novas versões do projeto original (release) e reinicia um proxy em execução.

Não atives os dois componentes ao mesmo tempo: o apt instala sempre a versão mais alta, que normalmente é uma compilação diária. Para mudar uma instalação existente de main para release, altera o componente em /etc/apt/sources.list.d/openelp-db9cr.list, executa sudo apt update e depois instala explicitamente a versão release (normalmente um downgrade, ou seja, uma versão anterior), p. ex. sudo apt install openelp=0.9.3-1~trixie.

Rede e firewall

Os clientes EchoLink ligam-se ao proxy por TCP na Port configurada (predefinição 8100). O próprio proxy tem de estar acessível a partir da Internet nas portas UDP 5198 e 5199 (reencaminha-as no teu router se o proxy estiver atrás de NAT) e precisa de acesso de saída à porta TCP 5200 e às portas UDP 5198/5199. Permite que apenas os teus próprios clientes acedam à porta do proxy, a menos que operes um proxy público.

Usar o proxy com o SvxLink

Na configuração do módulo EchoLink do SvxLink (/etc/svxlink/svxlink.d/ModuleEchoLink.conf), indica o proxy e reinicia o SvxLink:

PROXY_SERVER=192.0.2.10    # endereço do anfitrião OpenELP
PROXY_PORT=8100
PROXY_PASSWORD=your-password

O cliente EchoLink oficial para PC configura-se da mesma forma em Setup → Connections → Proxy.

Aplicar alterações de configuração

O OpenELP só lê a sua configuração no arranque. Depois de editar /etc/openelp/ELProxy.conf, reinicia o serviço (isto termina as ligações de clientes ativas):

sudo systemctl restart openelp.service

As alterações locais a /etc/openelp/ELProxy.conf são mantidas nas atualizações (é um ficheiro de configuração do dpkg). O ficheiro só pode ser lido pelo root, uma vez que contém a palavra-passe do proxy.

Instalar uma versão mais antiga

As versões recentes continuam disponíveis no pool durante algum tempo depois de serem substituídas (diárias durante uma semana, semanais durante um mês, mensais durante um ano — vê "Retention" (retenção) em UPSTREAM-SYNC.MD), pelo que normalmente é possível reverter uma compilação diária com problemas. Os pacotes das versões do projeto original (componente release) nunca são removidos:

apt list -a openelp   # lista todas as versões ainda presentes no repositório
sudo apt install openelp=0.9.4~dev+daily20261108.12.1.g0123456789ab-1~trixie
sudo apt-mark hold openelp   # opcional: impede que "apt upgrade" o volte a atualizar
# sudo apt-mark unhold openelp   # mais tarde, para retomar as atualizações automáticas

Sistemas de 32 bits: os pacotes armhf são compilados para Raspbian (ARMv6+VFP), a base do Raspberry Pi OS de 32 bits, pelo que funcionam em todos os modelos de Raspberry Pi, incluindo o Pi 1, o Zero e o Zero W, e também se instalam no Debian armhf (ambos são testados). i386 (PCs de 32 bits) só é compilado para o Debian 12: o Debian 13 já não suporta a instalação de sistemas i386. Os pacotes de 32 bits oferecem as mesmas funcionalidades que os de 64 bits.
