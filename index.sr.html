OpenELP DB9CR APT репозиторијум

⚠ Ова страница је аутоматски преведена помоћу вештачке интелигенције и може садржати грешке. Меродавна је енглеска верзија. (English)

Пакети OpenELP-а, EchoLink проксија отвореног кода, за Raspberry Pi OS и Debian, у две компоненте — изабери једну:

  • main: дневне развојне верзије из најновијег изворног кода овог форка, а не стабилна издања.
  • release: званична upstream издања OpenELP-а (0.9.3 и новија), изграђена из неизмењеног изворног кода upstream издања са истим подешавањима изградње као и дневни пакети. Свако издање се чува; apt upgrade прелази на свако ново upstream издање.

Детаље потражи у репозиторијуму изворног кода.

Upstream и локалне измене

Ово је свакодневно синхронизован форк пројекта cottsay/openelp, оригиналног пројекта OpenELP, са локалним паковањем (овај APT репозиторијум) и евентуалним додатним изменама поврх њега. Ако у било ком тренутку желиш тачно да видиш шта се разликује у односу на upstream, упореди тренутно стање на GitHub-у: upstream main … main овог форка.

Брзи почетак

Покрени на циљном систему (одговарајуће кодно име и архитектура се откривају аутоматски):

# Увоз јавног кључа за потписивање
curl -fsSL https://criede.github.io/openelp/pubkey.gpg | \
  sudo gpg --dearmor -o /usr/share/keyrings/openelp-db9cr.gpg

# Додавање извора репозиторијума. Изабери компоненту:
#   main     дневне развојне верзије
#   release  званична upstream издања (0.9.3 и новија)
component=release
codename=$(sed -n 's/^VERSION_CODENAME=//p' /etc/os-release | tr -d '"')
arch=$(dpkg --print-architecture)
echo "deb [signed-by=/usr/share/keyrings/openelp-db9cr.gpg arch=${arch}] https://criede.github.io/openelp ${codename} ${component}" | \
  sudo tee /etc/apt/sources.list.d/openelp-db9cr.list

sudo apt update
sudo apt install openelp

# Обавезно пре првог покретања: постави лозинку (и по жељи
# порт, адресе за слушање, регистрацију и филтере позивних знакова).
sudo editor /etc/openelp/ELProxy.conf

# Омогућавање покретања проксија при подизању система и покретање одмах.
sudo systemctl enable --now openelp.service

# Провера стања сервиса и праћење његовог дневника.
systemctl status openelp.service
journalctl -u openelp.service -f

Обавезно: Прокси одбија да се покрене док је Password у /etc/openelp/ELProxy.conf и даље notset. Изабери сопствену лозинку; постави је на PUBLIC само ако желиш да покренеш јавни прокси (заједно са јединственим RegistrationName).

Ако apt update за овај извор пријави грешку 404, пакети за кодно име твог система још се не граде (погледај табелу испод) — уместо тога промени кодно име у /etc/apt/sources.list.d/openelp-db9cr.list у неко од подржаних. Након тога уобичајени sudo apt upgrade аутоматски преузима нове дневне верзије (main) или нова upstream издања (release) и поново покреће активни прокси.

Немој истовремено омогућити обе компоненте: apt увек инсталира вишу верзију, а то је обично дневна верзија. Ако постојећу инсталацију желиш да пребациш са main на release, промени компоненту у /etc/apt/sources.list.d/openelp-db9cr.list, покрени sudo apt update, а затим експлицитно инсталирај верзију издања (обично је то враћање на нижу верзију), нпр. sudo apt install openelp=0.9.3-1~trixie.

Мрежа и заштитни зид

EchoLink клијенти се повезују на прокси преко TCP-а на подешеном порту Port (подразумевано 8100). Сам прокси мора бити доступан са интернета на UDP портовима 5198 и 5199 (проследи их на рутеру ако је прокси иза NAT-а) и потребан му је одлазни приступ TCP порту 5200 и UDP портовима 5198/5199. Дозволи приступ порту проксија само сопственим клијентима, осим ако покрећеш јавни прокси.

Коришћење проксија са SvxLink-ом

У конфигурацији EchoLink модула за SvxLink (/etc/svxlink/svxlink.d/ModuleEchoLink.conf) усмери га на прокси и поново покрени SvxLink:

PROXY_SERVER=192.0.2.10    # адреса рачунара са OpenELP-ом
PROXY_PORT=8100
PROXY_PASSWORD=your-password

Званични EchoLink клијент за PC подешава се на исти начин у Setup → Connections → Proxy.

Примена измена конфигурације

OpenELP чита своју конфигурацију само при покретању. Након уређивања /etc/openelp/ELProxy.conf поново покрени сервис (тиме се прекидају активне везе клијената):

sudo systemctl restart openelp.service

Локалне измене у /etc/openelp/ELProxy.conf задржавају се при надоградњама (то је dpkg конфигурациона датотека). Датотеку може да чита само root, јер садржи лозинку проксија.

Инсталирање старије верзије

Недавне верзије остају доступне у pool-у неко време након што их замене новије (дневне недељу дана, недељне месец дана, месечне годину дана — погледај одељак „Retention“ (задржавање) у UPSTREAM-SYNC.MD), па се лоша дневна верзија обично може вратити. Пакети upstream издања (компонента release) никада се не уклањају:

apt list -a openelp   # приказује све верзије које су још у репозиторијуму
sudo apt install openelp=0.9.4~dev+daily20261108.12.1.g0123456789ab-1~trixie
sudo apt-mark hold openelp   # опционо: спречава да га "apt upgrade" поново ажурира
# sudo apt-mark unhold openelp   # касније, за наставак аутоматских ажурирања

Пакети

ПакетСадржај
openelpПрокси демон openelpd и његова библиотека, пример конфигурације /etc/openelp/ELProxy.conf, systemd сервис (openelp.service, не омогућава се аутоматски) и страница приручника. Изграђен уз системску библиотеку PCRE2, са уграђеном имплементацијом MD5 (без зависности од OpenSSL-а) и бележењем преко syslog-а. Развојна заглавља нису укључена.

32-битни системи: пакети armhf граде се за Raspbian (ARMv6+VFP), основу 32-битног Raspberry Pi OS-а, тако да раде на сваком моделу Raspberry Pi, укључујући Pi 1, Zero и Zero W, а инсталирају се и на Debian armhf (оба су тестирана). i386 (32-битни PC рачунари) се гради само за Debian 12: Debian 13 више не подржава инсталирање i386 система. 32-битни пакети садрже исте функције као и 64-битни.
