OpenELP DB9CR APT-Repository

⚠ Diese Seite wurde automatisch mit künstlicher Intelligenz übersetzt und kann Fehler enthalten. Maßgeblich ist die englische Fassung. (English)

Pakete von OpenELP, dem Open-Source-EchoLink-Proxy, für Raspberry Pi OS und Debian, in zwei Komponenten — wähle eine aus:

  • main: tägliche Entwicklungs-Builds aus dem neuesten Quellcode dieses Forks, keine stabilen Releases.
  • release: die offiziellen Upstream-Releases von OpenELP (0.9.3 und neuer), gebaut aus dem unveränderten Upstream-Release-Quellcode mit denselben Build-Einstellungen wie die täglichen Pakete. Jedes Release bleibt erhalten; apt upgrade wechselt jeweils auf das neue Upstream-Release.

Details findest du im Quellcode-Repository.

Upstream & lokale Änderungen

Dies ist ein täglich synchronisierter Fork von cottsay/openelp, dem ursprünglichen OpenELP-Projekt, mit eigener Paketierung (dieses APT-Repository) und gegebenenfalls weiteren Änderungen darüber. Um jederzeit genau zu sehen, was sich vom Upstream unterscheidet, vergleiche live auf GitHub: Upstream-main … main dieses Forks.

Schnellstart

Auf dem Zielsystem ausführen (Codename und Architektur werden automatisch erkannt):

# Öffentlichen Signaturschlüssel importieren
curl -fsSL https://criede.github.io/openelp/pubkey.gpg | \
  sudo gpg --dearmor -o /usr/share/keyrings/openelp-db9cr.gpg

# Repository-Quelle hinzufügen. Komponente wählen:
#   main     tägliche Entwicklungs-Builds
#   release  offizielle Upstream-Releases (0.9.3 und neuer)
component=release
codename=$(sed -n 's/^VERSION_CODENAME=//p' /etc/os-release | tr -d '"')
arch=$(dpkg --print-architecture)
echo "deb [signed-by=/usr/share/keyrings/openelp-db9cr.gpg arch=${arch}] https://criede.github.io/openelp ${codename} ${component}" | \
  sudo tee /etc/apt/sources.list.d/openelp-db9cr.list

sudo apt update
sudo apt install openelp

# Vor dem ersten Start zwingend: ein Passwort setzen (und optional den
# Port, die Bind-Adressen, die Registrierung und die Rufzeichenfilter).
sudo editor /etc/openelp/ELProxy.conf

# Den Proxy beim Booten aktivieren und sofort starten.
sudo systemctl enable --now openelp.service

# Dienststatus prüfen und das Log verfolgen.
systemctl status openelp.service
journalctl -u openelp.service -f

Erforderlich: Der Proxy startet nicht, solange Password in /etc/openelp/ELProxy.conf noch notset ist. Wähle ein eigenes Passwort; setze es nur dann auf PUBLIC, wenn du einen öffentlichen Proxy betreiben möchtest (zusammen mit einem eindeutigen RegistrationName).

Meldet apt update für diese Quelle einen 404-Fehler, wird der Codename deines Systems noch nicht gebaut (siehe Tabelle unten) — ändere den Codename in /etc/apt/sources.list.d/openelp-db9cr.list stattdessen auf einen der unterstützten. Danach übernimmt ein normales sudo apt upgrade neue tägliche Builds (main) bzw. neue Upstream-Releases (release) automatisch und startet einen laufenden Proxy neu.

Aktiviere nicht beide Komponenten gleichzeitig: apt installiert immer die höhere Version, und das ist in der Regel ein täglicher Build. Um eine bestehende Installation von main auf release umzustellen, ändere die Komponente in /etc/apt/sources.list.d/openelp-db9cr.list, führe sudo apt update aus und installiere dann die Release-Version explizit (in der Regel ein Downgrade), z. B. sudo apt install openelp=0.9.3-1~trixie.

Netzwerk und Firewall

EchoLink-Clients verbinden sich per TCP über den konfigurierten Port (Standard 8100) mit dem Proxy. Der Proxy selbst muss aus dem Internet über die UDP-Ports 5198 und 5199 erreichbar sein (leite diese an deinem Router weiter, wenn der Proxy hinter NAT steht) und benötigt ausgehenden Zugriff auf TCP-Port 5200 sowie die UDP-Ports 5198/5199. Lass nur deine eigenen Clients auf den Proxy-Port zugreifen, sofern du keinen öffentlichen Proxy betreibst.

Den Proxy mit SvxLink verwenden

Trage in der Konfiguration des EchoLink-Moduls von SvxLink (/etc/svxlink/svxlink.d/ModuleEchoLink.conf) den Proxy ein und starte SvxLink neu:

PROXY_SERVER=192.0.2.10    # Adresse des OpenELP-Hosts
PROXY_PORT=8100
PROXY_PASSWORD=your-password

Der offizielle EchoLink-PC-Client wird auf dieselbe Weise unter Setup → Connections → Proxy konfiguriert.

Konfigurationsänderungen übernehmen

OpenELP liest seine Konfiguration nur beim Start. Starte nach dem Bearbeiten von /etc/openelp/ELProxy.conf den Dienst neu (dabei werden aktive Client-Verbindungen getrennt):

sudo systemctl restart openelp.service

Lokale Änderungen an /etc/openelp/ELProxy.conf bleiben bei Upgrades erhalten (es ist eine dpkg-Konfigurationsdatei). Die Datei ist nur für root lesbar, da sie das Proxy-Passwort enthält.

Eine ältere Version installieren

Neuere Versionen bleiben nach ihrer Ablösung noch eine Weile im Pool verfügbar (täglich für eine Woche, wöchentlich für einen Monat, monatlich für ein Jahr — siehe „Retention“ (Aufbewahrung) in UPSTREAM-SYNC.MD), sodass ein fehlerhafter täglicher Build in der Regel zurückgerollt werden kann. Pakete der Upstream-Releases (Komponente release) werden nie entfernt:

apt list -a openelp   # listet alle Versionen auf, die noch im Repository liegen
sudo apt install openelp=0.9.4~dev+daily20261108.12.1.g0123456789ab-1~trixie
sudo apt-mark hold openelp   # optional: verhindert, dass "apt upgrade" es wieder aktualisiert
# sudo apt-mark unhold openelp   # später, um automatische Updates fortzusetzen

32-Bit-Systeme: armhf-Pakete werden gegen Raspbian (ARMv6+VFP) gebaut, die Basis des 32-Bit-Raspberry-Pi-OS, sodass sie auf jedem Raspberry-Pi-Modell laufen, einschließlich Pi 1, Zero und Zero W, und sich auch auf Debian armhf installieren lassen (beides ist getestet). i386 (32-Bit-PCs) wird nur für Debian 12 gebaut: Debian 13 unterstützt die Installation von i386-Systemen nicht mehr. Die 32-Bit-Pakete bieten dieselben Funktionen wie die 64-Bit-Pakete.
