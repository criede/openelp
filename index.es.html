Repositorio APT OpenELP DB9CR

⚠ Esta página ha sido traducida automáticamente mediante inteligencia artificial y puede contener errores. La versión en inglés es la de referencia. (English)

Paquetes de OpenELP, el proxy EchoLink de código abierto, para Raspberry Pi OS y Debian, en dos componentes — elige uno:

  • main: compilaciones de desarrollo diarias a partir del código fuente más reciente de este fork, no versiones estables.
  • release: las versiones oficiales de OpenELP del proyecto original (0.9.3 y posteriores), compiladas a partir del código fuente original sin modificar con la misma configuración de compilación que los paquetes diarios. Se conservan todas las versiones; apt upgrade pasa a cada nueva versión del proyecto original.

Consulta el repositorio del código fuente para más detalles.

Proyecto original (upstream) & cambios locales

Este es un fork sincronizado a diario de cottsay/openelp, el proyecto OpenELP original, con empaquetado local (este repositorio APT) y posiblemente otros cambios añadidos encima. Para ver exactamente en qué se diferencia del proyecto original en cualquier momento, compara en directo en GitHub: main del proyecto original … main de este fork.

Inicio rápido

Ejecuta en el sistema de destino (detecta automáticamente el nombre en clave y la arquitectura correctos):

# Importar la clave pública de firma
curl -fsSL https://criede.github.io/openelp/pubkey.gpg | \
  sudo gpg --dearmor -o /usr/share/keyrings/openelp-db9cr.gpg

# Añadir la fuente del repositorio. Elige el componente:
#   main     compilaciones de desarrollo diarias
#   release  versiones oficiales del proyecto original (0.9.3 y posteriores)
component=release
codename=$(sed -n 's/^VERSION_CODENAME=//p' /etc/os-release | tr -d '"')
arch=$(dpkg --print-architecture)
echo "deb [signed-by=/usr/share/keyrings/openelp-db9cr.gpg arch=${arch}] https://criede.github.io/openelp ${codename} ${component}" | \
  sudo tee /etc/apt/sources.list.d/openelp-db9cr.list

sudo apt update
sudo apt install openelp

# Obligatorio antes del primer arranque: establecer una contraseña (y, opcionalmente,
# el puerto, las direcciones de escucha, el registro y los filtros de indicativos).
sudo editor /etc/openelp/ELProxy.conf

# Habilitar el proxy al arrancar e iniciarlo ahora.
sudo systemctl enable --now openelp.service

# Comprobar el estado del servicio y seguir su registro.
systemctl status openelp.service
journalctl -u openelp.service -f

Obligatorio: el proxy se niega a arrancar mientras Password en /etc/openelp/ELProxy.conf siga siendo notset. Elige una contraseña propia; establécela en PUBLIC solo si quieres operar un proxy público (junto con un RegistrationName único).

Si apt update informa de un error 404 para esta fuente, el nombre en clave de tu sistema aún no se compila (mira la tabla de abajo) — en vez de eso, cambia el nombre en clave en /etc/apt/sources.list.d/openelp-db9cr.list por uno de los compatibles. Después, un sudo apt upgrade normal obtiene automáticamente las nuevas compilaciones diarias (main) o las nuevas versiones del proyecto original (release) y reinicia un proxy en ejecución.

No habilites ambos componentes a la vez: apt siempre instala la versión más alta, que suele ser una compilación diaria. Para cambiar una instalación existente de main a release, cambia el componente en /etc/apt/sources.list.d/openelp-db9cr.list, ejecuta sudo apt update y, a continuación, instala explícitamente la versión release (normalmente un downgrade, es decir, una versión anterior), p. ej. sudo apt install openelp=0.9.3-1~trixie.

Red y cortafuegos

Los clientes EchoLink se conectan al proxy por TCP en el Port configurado (por defecto 8100). El propio proxy debe ser accesible desde Internet en los puertos UDP 5198 y 5199 (redirígelos en tu router si el proxy está detrás de NAT) y necesita acceso saliente al puerto TCP 5200 y a los puertos UDP 5198/5199. Permite que solo tus propios clientes accedan al puerto del proxy, a menos que operes un proxy público.

Uso del proxy con SvxLink

En la configuración del módulo EchoLink de SvxLink (/etc/svxlink/svxlink.d/ModuleEchoLink.conf), indica el proxy y reinicia SvxLink:

PROXY_SERVER=192.0.2.10    # dirección del equipo con OpenELP
PROXY_PORT=8100
PROXY_PASSWORD=your-password

El cliente oficial EchoLink para PC se configura de la misma manera en Setup → Connections → Proxy.

Aplicar cambios de configuración

OpenELP solo lee su configuración al arrancar. Después de editar /etc/openelp/ELProxy.conf, reinicia el servicio (esto corta las conexiones de clientes activas):

sudo systemctl restart openelp.service

Los cambios locales en /etc/openelp/ELProxy.conf se conservan en las actualizaciones (es un archivo de configuración de dpkg). El archivo solo puede leerlo root, ya que contiene la contraseña del proxy.

Instalar una versión anterior

Las versiones recientes siguen disponibles en el pool durante un tiempo después de ser reemplazadas (las diarias durante una semana, las semanales durante un mes, las mensuales durante un año — consulta «Retention» (retención) en UPSTREAM-SYNC.MD), por lo que normalmente se puede revertir una compilación diaria defectuosa. Los paquetes de versiones del proyecto original (componente release) nunca se eliminan:

apt list -a openelp   # lista todas las versiones que siguen en el repositorio
sudo apt install openelp=0.9.4~dev+daily20261108.12.1.g0123456789ab-1~trixie
sudo apt-mark hold openelp   # opcional: impide que "apt upgrade" lo vuelva a actualizar
# sudo apt-mark unhold openelp   # más tarde, para reanudar las actualizaciones automáticas

Sistemas de 32 bits: los paquetes armhf se compilan para Raspbian (ARMv6+VFP), la base de Raspberry Pi OS de 32 bits, por lo que funcionan en todos los modelos de Raspberry Pi, incluidos el Pi 1, el Zero y el Zero W, y también se instalan en Debian armhf (ambos están probados). i386 (PC de 32 bits) solo se compila para Debian 12: Debian 13 ya no admite la instalación de sistemas i386. Los paquetes de 32 bits ofrecen las mismas funciones que los de 64 bits.
