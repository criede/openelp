Dépôt APT OpenELP DB9CR

⚠ Cette page a été traduite automatiquement par intelligence artificielle et peut contenir des erreurs. La version anglaise fait foi. (English)

Paquets d'OpenELP, le proxy EchoLink open source, pour Raspberry Pi OS et Debian, en deux composants — choisis-en un :

  • main : compilations de développement quotidiennes à partir des sources les plus récentes de ce fork, pas des versions stables.
  • release : les versions officielles d'OpenELP en amont (0.9.3 et ultérieures), compilées à partir des sources non modifiées de la version amont avec les mêmes paramètres de compilation que les paquets quotidiens. Chaque version est conservée ; apt upgrade passe à chaque nouvelle version amont.

Consulte le dépôt des sources pour plus de détails.

Amont & modifications locales

Ceci est un fork synchronisé quotidiennement de cottsay/openelp, le projet OpenELP d'origine, avec un empaquetage local (ce dépôt APT) et éventuellement d'autres modifications par-dessus. Pour voir exactement ce qui diffère de l'amont à tout moment, compare en direct sur GitHub : main amont … main de ce fork.

Démarrage rapide

À exécuter sur le système cible (détecte automatiquement le nom de code et l'architecture) :

# Importer la clé publique de signature
curl -fsSL https://criede.github.io/openelp/pubkey.gpg | \
  sudo gpg --dearmor -o /usr/share/keyrings/openelp-db9cr.gpg

# Ajouter la source du dépôt. Choisir le composant :
#   main     compilations de développement quotidiennes
#   release  versions officielles amont (0.9.3 et ultérieures)
component=release
codename=$(sed -n 's/^VERSION_CODENAME=//p' /etc/os-release | tr -d '"')
arch=$(dpkg --print-architecture)
echo "deb [signed-by=/usr/share/keyrings/openelp-db9cr.gpg arch=${arch}] https://criede.github.io/openelp ${codename} ${component}" | \
  sudo tee /etc/apt/sources.list.d/openelp-db9cr.list

sudo apt update
sudo apt install openelp

# Obligatoire avant le premier démarrage : définir un mot de passe (et éventuellement
# le port, les adresses d'écoute, l'enregistrement et les filtres d'indicatifs).
sudo editor /etc/openelp/ELProxy.conf

# Activer le proxy au démarrage et le lancer immédiatement.
sudo systemctl enable --now openelp.service

# Vérifier l'état du service et suivre son journal.
systemctl status openelp.service
journalctl -u openelp.service -f

Obligatoire : le proxy refuse de démarrer tant que Password dans /etc/openelp/ELProxy.conf vaut encore notset. Choisis ton propre mot de passe ; ne le définis à PUBLIC que si tu veux exploiter un proxy public (avec un RegistrationName unique).

Si apt update signale une erreur 404 pour cette source, le nom de code de ton système n'est pas encore compilé (voir le tableau ci-dessous) — modifie plutôt le nom de code dans /etc/apt/sources.list.d/openelp-db9cr.list pour l'un de ceux pris en charge. Ensuite, un sudo apt upgrade ordinaire récupère automatiquement les nouvelles compilations quotidiennes (main) ou les nouvelles versions amont (release) et redémarre un proxy en cours d'exécution.

N'active pas les deux composants à la fois : apt installe toujours la version la plus élevée, qui est généralement une compilation quotidienne. Pour faire passer une installation existante de main à release, change le composant dans /etc/apt/sources.list.d/openelp-db9cr.list, exécute sudo apt update, puis installe explicitement la version release (généralement une rétrogradation), par ex. sudo apt install openelp=0.9.3-1~trixie.

Réseau et pare-feu

Les clients EchoLink se connectent au proxy en TCP sur le Port configuré (par défaut 8100). Le proxy lui-même doit être joignable depuis Internet sur les ports UDP 5198 et 5199 (redirige-les sur ton routeur si le proxy est derrière un NAT) et a besoin d'un accès sortant au port TCP 5200 et aux ports UDP 5198/5199. N'autorise que tes propres clients à accéder au port du proxy, sauf si tu exploites un proxy public.

Utiliser le proxy avec SvxLink

Dans la configuration du module EchoLink de SvxLink (/etc/svxlink/svxlink.d/ModuleEchoLink.conf), indique le proxy et redémarre SvxLink :

PROXY_SERVER=192.0.2.10    # adresse de l'hôte OpenELP
PROXY_PORT=8100
PROXY_PASSWORD=your-password

Le client PC officiel EchoLink se configure de la même manière sous Setup → Connections → Proxy.

Appliquer les modifications de configuration

OpenELP ne lit sa configuration qu'au démarrage. Après avoir modifié /etc/openelp/ELProxy.conf, redémarre le service (cela coupe les connexions clientes actives) :

sudo systemctl restart openelp.service

Les modifications locales de /etc/openelp/ELProxy.conf sont conservées lors des mises à niveau (c'est un fichier de configuration dpkg). Le fichier n'est lisible que par root, car il contient le mot de passe du proxy.

Installer une version plus ancienne

Les versions récentes restent disponibles dans le pool pendant un certain temps après avoir été remplacées (quotidiennes pendant une semaine, hebdomadaires pendant un mois, mensuelles pendant un an — voir « Retention » (conservation) dans UPSTREAM-SYNC.MD), de sorte qu'une mauvaise compilation quotidienne peut généralement être annulée. Les paquets des versions amont (composant release) ne sont jamais supprimés :

apt list -a openelp   # liste toutes les versions encore présentes dans le dépôt
sudo apt install openelp=0.9.4~dev+daily20261108.12.1.g0123456789ab-1~trixie
sudo apt-mark hold openelp   # facultatif : empêche "apt upgrade" de le remettre à jour
# sudo apt-mark unhold openelp   # plus tard, pour reprendre les mises à jour automatiques

Systèmes 32 bits : les paquets armhf sont compilés pour Raspbian (ARMv6+VFP), la base de Raspberry Pi OS 32 bits, de sorte qu'ils fonctionnent sur tous les modèles de Raspberry Pi, y compris le Pi 1, le Zero et le Zero W, et s'installent aussi sur Debian armhf (les deux sont testés). i386 (PC 32 bits) n'est compilé que pour Debian 12 : Debian 13 ne prend plus en charge l'installation de systèmes i386. Les paquets 32 bits offrent les mêmes fonctionnalités que les paquets 64 bits.
