OpenELP DB9CR APT-Repository

⚠ Dës Säit gouf automatesch mat kënschtlecher Intelligenz iwwersat a ka Feeler enthalen. Déi englesch Versioun ass déi mossgeeblech. (English)

Pakete vun OpenELP, dem Open-Source-EchoLink-Proxy, fir Raspberry Pi OS an Debian, an zwou Komponenten — wiel der eng aus:

  • main: deeglech Entwécklungs-Builds aus dem neiste Quellcode vun dësem Fork, keng stabil Releases.
  • release: déi offiziell Upstream-Releases vun OpenELP (0.9.3 an méi nei), gebaut aus dem onverännerte Upstream-Release-Quellcode mat deene selwechte Build-Astellungen wéi déi deeglech Paketen. All Release gëtt behalen; apt upgrade wiesselt all Kéier op dat neit Upstream-Release.

Detailer fënns du am Quellcode-Repository.

Upstream & lokal Ännerungen

Dëst ass en deeglech synchroniséierte Fork vun cottsay/openelp, dem ursprénglechen OpenELP-Projet, mat eegener Paketéierung (dëse APT-Repository) an eventuell weidere Ännerungen doriwwer. Fir zu all Moment genee ze gesinn, wat sech vum Upstream ënnerscheet, vergläich live op GitHub: Upstream-main … main vun dësem Fork.

Sécherheet: D'main-Pakete verwerfen Paketen aus dem EchoLink-Netz, déi bekannte SvxLink-Schwachstellen ausléise géifen, ier se e SvxLink-Knuet erreechen, deen dëse Proxy benotzt: fehlerhaft Info-/Chat-Pakete vum Typ NDATA (CVE-2026-73152 / GHSA-2m63-p9h9-p5rf: Ofstuerz, Offeleeë vu Späicherinhalt) a Pakete vum Typ RTCP SDES mat engem Ruffzeechen, dat ongëlteg Zeechen oder méi wéi 32 Zeechen enthält (GHSA-6w9x-486p-ggrj: TCL-Befeelsinjektioun, Bufferiwwerleef). Ausserdeem limitéiere se d'Zäit, déi e Client sech fir d'Umeldung huele kann. Dat ass eng Noutléisung a keen Ersatz fir en Update vu SvxLink op 26.05.2 oder méi nei. D'release-Pakete enthalen onverännerten Upstream-Quellcode ouni dës Ännerungen; béid bedreiwen de Proxy an enger systemd-Sandbox.

Séier Ufank

Um Zilsystem ausféieren (Codename an Architektur ginn automatesch erkannt):

# Den ëffentlechen Ënnerschrëftsschlëssel importéieren
curl -fsSL https://criede.github.io/openelp/pubkey.gpg | \
  sudo gpg --dearmor -o /usr/share/keyrings/openelp-db9cr.gpg

# D'Repository-Quell derbäisetzen. Komponent wielen:
#   main     deeglech Entwécklungs-Builds
#   release  offiziell Upstream-Releases (0.9.3 a méi nei)
component=release
codename=$(sed -n 's/^VERSION_CODENAME=//p' /etc/os-release | tr -d '"')
arch=$(dpkg --print-architecture)
echo "deb [signed-by=/usr/share/keyrings/openelp-db9cr.gpg arch=${arch}] https://criede.github.io/openelp ${codename} ${component}" | \
  sudo tee /etc/apt/sources.list.d/openelp-db9cr.list

sudo apt update
sudo apt install openelp

# Obligatoresch virum éischte Start: e Passwuert setzen (an optional de
# Port, d'Bind-Adressen, d'Registréierung an d'Ruffzeechefilteren).
sudo editor /etc/openelp/ELProxy.conf

# De Proxy beim Booten aktivéieren an elo starten.
sudo systemctl enable --now openelp.service

# De Servicestatus kontrolléieren an de Log verfollegen.
systemctl status openelp.service
journalctl -u openelp.service -f

Erfuerderlech: De Proxy start net, soulaang Password an /etc/openelp/ELProxy.conf nach ëmmer notset ass. Wiel däin eegent Passwuert; setz et just op PUBLIC, wann s du en ëffentleche Proxy bedreiwe wëlls (zesumme mat engem eendeitegen RegistrationName).

Wann apt update fir dës Quell en 404 mellt, gëtt de Codename vun dengem System nach net gebaut (kuck d'Tabell hei ënnen) — änner dann de Codename an /etc/apt/sources.list.d/openelp-db9cr.list op ee vun deenen ënnerstëtzten. Duerno hëlt en normalt sudo apt upgrade automatesch nei deeglech Builds (main) oder nei Upstream-Releases (release) a start e lafende Proxy nei.

Aktivéier net béid Komponenten gläichzäiteg: apt installéiert ëmmer déi méi héich Versioun, an dat ass normalerweis en deegleche Build. Fir eng bestehend Installatioun vu main op release ëmzestellen, änner de Komponent an /etc/apt/sources.list.d/openelp-db9cr.list, féier sudo apt update aus an installéier dann d'Release-Versioun explizit (normalerweis en Downgrade), z. B. sudo apt install openelp=0.9.3-2~trixie.

Netzwierk a Firewall

EchoLink-Clientë verbannen sech iwwer TCP um konfiguréierte Port (Standard 8100) mam Proxy. De Proxy selwer muss vum Internet aus iwwer d'UDP-Ports 5198 an 5199 erreechbar sinn (leed se op dengem Router weider, wann de Proxy hannert NAT steet) a brauch erausgoenden Zougrëff op den TCP-Port 5200 an d'UDP-Ports 5198/5199. Looss just deng eege Clienten op de Proxy-Port zougräifen, ausser du bedreifs en ëffentleche Proxy.

De Proxy mat SvxLink benotzen

Gëff an der Konfiguratioun vum EchoLink-Modul vu SvxLink (/etc/svxlink/svxlink.d/ModuleEchoLink.conf) de Proxy un a start SvxLink nei:

PROXY_SERVER=192.0.2.10    # Adress vum OpenELP-Host
PROXY_PORT=8100
PROXY_PASSWORD=your-password

Den offiziellen EchoLink-PC-Client gëtt op déi selwecht Aart a Weis ënner Setup → Connections → Proxy konfiguréiert.

Konfiguratiounsännerungen iwwerhuelen

OpenELP liest seng Konfiguratioun just beim Start. Nodeems du /etc/openelp/ELProxy.conf geännert hues, start de Service nei (dobäi ginn aktiv Client-Verbindungen ofgebrach):

sudo systemctl restart openelp.service

Lokal Ännerungen un /etc/openelp/ELProxy.conf bleiwen bei Upgrades erhalen (et ass eng dpkg-Konfiguratiounsdatei). Well en d'Proxy-Passwuert enthält, ass de Fichier just fir root an d'Grupp openelp liesbar, ënner där de Service leeft.

Eng méi al Versioun installéieren

Rezent Versioune bleiwen nach eng Zäit am Pool disponibel, nodeems se ersat goufen (deeglech fir eng Woch, wöchentlech fir ee Mount, monatlech fir ee Joer — kuck „Retention“ (Bewaardauer) an UPSTREAM-SYNC.MD), sou datt e schlechten deegleche Build normalerweis zréckgesat ka ginn. Pakete vun Upstream-Releases (Komponent release) ginn ni geläscht:

apt list -a openelp   # weist all Versiounen, déi nach am Repository sinn
sudo apt install openelp=0.9.4~dev+daily20261108.12.1.g0123456789ab-1~trixie
sudo apt-mark hold openelp   # optional: verhënnert, datt "apt upgrade" et erëm aktualiséiert
# sudo apt-mark unhold openelp   # méi spéit, fir automatesch Updates erëm opzehuelen
