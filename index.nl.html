OpenELP DB9CR APT-repository

⚠ Deze pagina is automatisch vertaald met kunstmatige intelligentie en kan fouten bevatten. De Engelse versie is leidend. (English)

Pakketten van OpenELP, de open-source EchoLink-proxy, voor Raspberry Pi OS en Debian, in twee componenten — kies er één:

  • main: dagelijkse ontwikkelbuilds uit de nieuwste broncode van deze fork, geen stabiele releases.
  • release: de officiële upstream-releases van OpenELP (0.9.3 en nieuwer), gebouwd uit de ongewijzigde upstream-releasebroncode met dezelfde build-instellingen als de dagelijkse pakketten. Elke release blijft bewaard; apt upgrade stapt telkens over op de nieuwe upstream-release.

Zie de broncode-repository voor details.

Upstream & lokale wijzigingen

Dit is een dagelijks gesynchroniseerde fork van cottsay/openelp, het oorspronkelijke OpenELP-project, met eigen packaging (deze APT-repository) en mogelijk verdere wijzigingen daarbovenop. Om op elk moment precies te zien wat er verschilt van upstream, vergelijk je live op GitHub: upstream-main … main van deze fork.

Snelstart

Uitvoeren op het doelsysteem (detecteert automatisch de juiste codenaam/architectuur):

# De publieke ondertekeningssleutel importeren
curl -fsSL https://criede.github.io/openelp/pubkey.gpg | \
  sudo gpg --dearmor -o /usr/share/keyrings/openelp-db9cr.gpg

# De repository-bron toevoegen. Kies de component:
#   main     dagelijkse ontwikkelbuilds
#   release  officiële upstream-releases (0.9.3 en nieuwer)
component=release
codename=$(sed -n 's/^VERSION_CODENAME=//p' /etc/os-release | tr -d '"')
arch=$(dpkg --print-architecture)
echo "deb [signed-by=/usr/share/keyrings/openelp-db9cr.gpg arch=${arch}] https://criede.github.io/openelp ${codename} ${component}" | \
  sudo tee /etc/apt/sources.list.d/openelp-db9cr.list

sudo apt update
sudo apt install openelp

# Verplicht vóór de eerste start: een wachtwoord instellen (en optioneel de
# poort, bind-adressen, registratie en roepnaamfilters).
sudo editor /etc/openelp/ELProxy.conf

# De proxy bij het opstarten inschakelen en nu starten.
sudo systemctl enable --now openelp.service

# De servicestatus controleren en het log volgen.
systemctl status openelp.service
journalctl -u openelp.service -f

Vereist: de proxy weigert te starten zolang Password in /etc/openelp/ELProxy.conf nog notset is. Kies een eigen wachtwoord; stel het alleen in op PUBLIC als je een publieke proxy wilt draaien (samen met een unieke RegistrationName).

Als apt update voor deze bron een 404 meldt, wordt de codenaam van je systeem nog niet gebouwd (zie de tabel hieronder) — wijzig dan de codenaam in /etc/apt/sources.list.d/openelp-db9cr.list in een van de ondersteunde. Daarna haalt een gewone sudo apt upgrade automatisch nieuwe dagelijkse builds (main) of nieuwe upstream-releases (release) op en herstart een draaiende proxy.

Schakel niet beide componenten tegelijk in: apt installeert altijd de hoogste versie, en dat is meestal een dagelijkse build. Om een bestaande installatie van main naar release om te zetten, wijzig je de component in /etc/apt/sources.list.d/openelp-db9cr.list, voer je sudo apt update uit en installeer je daarna expliciet de releaseversie (meestal een downgrade), bijv. sudo apt install openelp=0.9.3-1~trixie.

Netwerk en firewall

EchoLink-clients maken via TCP verbinding met de proxy op de geconfigureerde Port (standaard 8100). De proxy zelf moet vanaf internet bereikbaar zijn op de UDP-poorten 5198 en 5199 (stuur ze door op je router als de proxy achter NAT staat) en heeft uitgaande toegang nodig tot TCP-poort 5200 en de UDP-poorten 5198/5199. Laat alleen je eigen clients de proxypoort bereiken, tenzij je een publieke proxy draait.

De proxy gebruiken met SvxLink

Stel in de configuratie van de EchoLink-module van SvxLink (/etc/svxlink/svxlink.d/ModuleEchoLink.conf) de proxy in en herstart SvxLink:

PROXY_SERVER=192.0.2.10    # adres van de OpenELP-host
PROXY_PORT=8100
PROXY_PASSWORD=your-password

De officiële EchoLink-pc-client wordt op dezelfde manier geconfigureerd onder Setup → Connections → Proxy.

Configuratiewijzigingen toepassen

OpenELP leest zijn configuratie alleen bij het starten. Herstart na het bewerken van /etc/openelp/ELProxy.conf de service (dit verbreekt actieve clientverbindingen):

sudo systemctl restart openelp.service

Lokale wijzigingen in /etc/openelp/ELProxy.conf blijven bij upgrades behouden (het is een dpkg-configuratiebestand). Het bestand is alleen leesbaar voor root, omdat het het proxywachtwoord bevat.

Een oudere versie installeren

Recente versies blijven na vervanging nog een tijd beschikbaar in de pool (dagelijks gedurende een week, wekelijks gedurende een maand, maandelijks gedurende een jaar — zie "Retention" (bewaartermijn) in UPSTREAM-SYNC.MD), zodat een slechte dagelijkse build meestal kan worden teruggedraaid. Pakketten van upstream-releases (component release) worden nooit verwijderd:

apt list -a openelp   # toont alle versies die nog in de repository staan
sudo apt install openelp=0.9.4~dev+daily20261108.12.1.g0123456789ab-1~trixie
sudo apt-mark hold openelp   # optioneel: voorkomt dat "apt upgrade" het weer bijwerkt
# sudo apt-mark unhold openelp   # later, om automatische updates te hervatten
