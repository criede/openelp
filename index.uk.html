APT-репозиторій OpenELP DB9CR

⚠ Цю сторінку перекладено автоматично за допомогою штучного інтелекту, тому вона може містити помилки. Чинною є англійська версія. (English)

Пакети OpenELP, проксі EchoLink з відкритим вихідним кодом, для Raspberry Pi OS і Debian у двох компонентах — вибери один:

  • main: щоденні збірки для розробки з найсвіжішого вихідного коду цього форку, а не стабільні релізи.
  • release: офіційні релізи OpenELP з upstream (0.9.3 і новіші), зібрані з незміненого вихідного коду upstream-релізу з тими самими параметрами збирання, що й щоденні пакети. Кожен реліз зберігається; apt upgrade переходить на кожен новий реліз upstream.

Подробиці дивись у репозиторії вихідного коду.

Upstream і локальні зміни

Це щоденно синхронізований форк cottsay/openelp, оригінального проєкту OpenELP, з локальним пакуванням (цей APT-репозиторій) і, можливо, подальшими змінами поверх нього. Щоб будь-коли точно побачити, чим форк відрізняється від upstream, порівняй актуальний стан на GitHub: upstream main … main цього форку.

Швидкий старт

Виконай на цільовій системі (потрібні кодова назва й архітектура визначаються автоматично):

# Імпорт відкритого ключа підпису
curl -fsSL https://criede.github.io/openelp/pubkey.gpg | \
  sudo gpg --dearmor -o /usr/share/keyrings/openelp-db9cr.gpg

# Додавання джерела репозиторію. Вибери компонент:
#   main     щоденні збірки для розробки
#   release  офіційні релізи upstream (0.9.3 і новіші)
component=release
codename=$(sed -n 's/^VERSION_CODENAME=//p' /etc/os-release | tr -d '"')
arch=$(dpkg --print-architecture)
echo "deb [signed-by=/usr/share/keyrings/openelp-db9cr.gpg arch=${arch}] https://criede.github.io/openelp ${codename} ${component}" | \
  sudo tee /etc/apt/sources.list.d/openelp-db9cr.list

sudo apt update
sudo apt install openelp

# Обов'язково перед першим запуском: задай пароль (і за бажанням
# порт, адреси прив'язки, реєстрацію та фільтри позивних).
sudo editor /etc/openelp/ELProxy.conf

# Увімкнути автозапуск проксі під час завантаження та запустити його зараз.
sudo systemctl enable --now openelp.service

# Перевірити стан служби та стежити за її журналом.
systemctl status openelp.service
journalctl -u openelp.service -f

Обов'язково: Проксі не запуститься, доки Password у /etc/openelp/ELProxy.conf досі має значення notset. Вибери власний пароль; встановлюй PUBLIC лише якщо хочеш запустити публічний проксі (разом з унікальним RegistrationName).

Якщо apt update повідомляє про помилку 404 для цього джерела, для кодової назви твоєї системи ще немає збірок (дивись таблицю нижче) — натомість зміни кодову назву в /etc/apt/sources.list.d/openelp-db9cr.list на одну з підтримуваних. Після цього звичайна команда sudo apt upgrade автоматично отримує нові щоденні збірки (main) або нові релізи upstream (release) і перезапускає запущений проксі.

Не вмикай обидва компоненти одночасно: apt завжди встановлює вищу версію, а це зазвичай щоденна збірка. Щоб перевести наявну інсталяцію з main на release, зміни компонент у /etc/apt/sources.list.d/openelp-db9cr.list, виконай sudo apt update, а потім явно встанови версію релізу (зазвичай це пониження версії), наприклад sudo apt install openelp=0.9.3-1~trixie.

Мережа та брандмауер

Клієнти EchoLink підключаються до проксі через TCP на налаштований Port (типово 8100). Сам проксі має бути доступним з Інтернету через UDP-порти 5198 і 5199 (перенаправ їх на маршрутизаторі, якщо проксі знаходиться за NAT) і потребує вихідного доступу до TCP-порту 5200 та UDP-портів 5198/5199. Дозволяй доступ до порту проксі лише своїм клієнтам, якщо ти не запускаєш публічний проксі.

Використання проксі з SvxLink

У конфігурації модуля EchoLink для SvxLink (/etc/svxlink/svxlink.d/ModuleEchoLink.conf) вкажи проксі та перезапусти SvxLink:

PROXY_SERVER=192.0.2.10    # адреса хоста OpenELP
PROXY_PORT=8100
PROXY_PASSWORD=your-password

Офіційний клієнт EchoLink для ПК налаштовується так само в розділі Setup → Connections → Proxy.

Застосування змін конфігурації

OpenELP зчитує свою конфігурацію лише під час запуску. Після редагування /etc/openelp/ELProxy.conf перезапусти службу (при цьому активні клієнтські з'єднання розриваються):

sudo systemctl restart openelp.service

Локальні зміни в /etc/openelp/ELProxy.conf зберігаються під час оновлень (це конфігураційний файл dpkg). Файл доступний для читання лише root, оскільки містить пароль проксі.

Встановлення старішої версії

Нещодавні версії залишаються доступними в пулі (pool) ще деякий час після заміни новішими (щоденні протягом тижня, щотижневі протягом місяця, щомісячні протягом року — дивись розділ «Retention» (зберігання) у UPSTREAM-SYNC.MD), тому невдалу щоденну збірку зазвичай можна відкотити. Пакети релізів upstream (компонент release) ніколи не видаляються:

apt list -a openelp   # показує всі версії, які ще є в репозиторії
sudo apt install openelp=0.9.4~dev+daily20261108.12.1.g0123456789ab-1~trixie
sudo apt-mark hold openelp   # необов'язково: не дає "apt upgrade" знову її оновити
# sudo apt-mark unhold openelp   # пізніше, щоб відновити автоматичні оновлення

Пакети

ПакетВміст
openelpДемон проксі openelpd і його бібліотека, приклад конфігурації /etc/openelp/ELProxy.conf, служба systemd (openelp.service, не вмикається автоматично) і сторінка довідки (man). Зібраний із системною бібліотекою PCRE2, з вбудованою реалізацією MD5 (без залежності від OpenSSL) і журналюванням через syslog. Заголовкові файли для розробки не включено.

Підтримувані системи

Кодова назваВідповідаєАрхітектури: main (щоденні)Архітектури: release
bookwormDebian 12, Raspberry Pi OS Bookworm (64/32 bit)amd64 arm64 armhf i386—

32-бітні системи: пакети armhf збираються для Raspbian (ARMv6+VFP), основи 32-бітної Raspberry Pi OS, тому вони працюють на всіх моделях Raspberry Pi, включно з Pi 1, Zero і Zero W, а також встановлюються на Debian armhf (обидва варіанти протестовано). i386 (32-бітні ПК) збирається лише для Debian 12: Debian 13 більше не підтримує встановлення систем i386. 32-бітні пакети містять ті самі функції, що й 64-бітні.

Ключ підпису

pubkey.gpg — імпортується автоматично командами швидкого старту вище.
