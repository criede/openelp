Repozitorij APT OpenELP DB9CR

⚠ To stran je samodejno prevedla umetna inteligenca in lahko vsebuje napake. Merodajna je angleška različica. (English)

Paketi OpenELP, odprtokodnega posredniškega strežnika (proxy) EchoLink, za Raspberry Pi OS in Debian, v dveh komponentah — izberi eno:

  • main: dnevne razvojne gradnje iz najnovejše izvorne kode tega forka, ne stabilne izdaje.
  • release: uradne izdaje OpenELP izvornega projekta (0.9.3 in novejše), zgrajene iz nespremenjene izvorne kode izdaje z enakimi nastavitvami gradnje kot dnevni paketi. Vsaka izdaja se ohrani; apt upgrade preide na vsako novo izdajo izvornega projekta.

Podrobnosti najdeš v izvornem repozitoriju.

Izvorni projekt in lokalne spremembe

To je dnevno sinhroniziran fork projekta cottsay/openelp, izvirnega projekta OpenELP, z lastnim pakiranjem (ta repozitorij APT) in morebitnimi nadaljnjimi spremembami. Če želiš kadar koli natančno videti, v čem se fork razlikuje od izvornega projekta, ju primerjaj v živo na GitHubu: main izvornega projekta … main tega forka.

Varnost: paketi main zavržejo pakete iz omrežja EchoLink, ki bi sprožili znane ranljivosti SvxLink, preden dosežejo vozlišče SvxLink, ki uporablja ta proxy: pokvarjene pakete NDATA vrste info/chat (CVE-2026-73152 / GHSA-2m63-p9h9-p5rf: sesutje, razkritje pomnilnika) in pakete RTCP SDES s klicnim znakom, ki vsebuje neveljavne znake ali je daljši od 32 znakov (GHSA-6w9x-486p-ggrj: vrivanje ukazov TCL, prekoračitve medpomnilnika). Omejijo tudi čas, ki ga ima odjemalec za prijavo. To je začasna rešitev, ne nadomestilo za posodobitev SvxLink na različico 26.05.2 ali novejšo. Paketi release vsebujejo nespremenjeno izvorno kodo izvornega projekta brez teh sprememb; oboji poganjajo proxy v peskovniku systemd.

Hiter začetek

Zaženi v ciljnem sistemu (pravilno kodno ime in arhitektura se zaznata samodejno):

# Uvoz javnega podpisnega ključa
curl -fsSL https://criede.github.io/openelp/pubkey.gpg | \
  sudo gpg --dearmor -o /usr/share/keyrings/openelp-db9cr.gpg

# Dodajanje vira repozitorija. Izberi komponento:
#   main     dnevne razvojne gradnje
#   release  uradne izdaje izvornega projekta (0.9.3 in novejše)
component=release
codename=$(sed -n 's/^VERSION_CODENAME=//p' /etc/os-release | tr -d '"')
arch=$(dpkg --print-architecture)
echo "deb [signed-by=/usr/share/keyrings/openelp-db9cr.gpg arch=${arch}] https://criede.github.io/openelp ${codename} ${component}" | \
  sudo tee /etc/apt/sources.list.d/openelp-db9cr.list

sudo apt update
sudo apt install openelp

# Obvezno pred prvim zagonom: nastavi geslo (in po želji
# vrata, naslove za poslušanje, registracijo in filtre klicnih znakov).
sudo editor /etc/openelp/ELProxy.conf

# Omogoči proxy ob zagonu sistema in ga zaženi zdaj.
sudo systemctl enable --now openelp.service

# Preveri stanje storitve in spremljaj njen dnevnik.
systemctl status openelp.service
journalctl -u openelp.service -f

Obvezno: Proxy se ne zažene, dokler ima Password v /etc/openelp/ELProxy.conf še vedno vrednost notset. Izberi svoje geslo; na PUBLIC ga nastavi le, če želiš upravljati javni proxy (skupaj z edinstvenim RegistrationName).

Če apt update za ta vir javi napako 404, za kodno ime tvojega sistema paketi še niso zgrajeni (glej tabelo spodaj) — kodno ime v /etc/apt/sources.list.d/openelp-db9cr.list zato spremeni v eno od podprtih. Nato običajni sudo apt upgrade samodejno prenese nove dnevne gradnje (main) ali nove izdaje izvornega projekta (release) in znova zažene delujoči proxy.

Ne omogočaj obeh komponent hkrati: apt vedno namesti višjo različico, ki je običajno dnevna gradnja. Če želiš obstoječo namestitev preklopiti z main na release, spremeni komponento v /etc/apt/sources.list.d/openelp-db9cr.list, zaženi sudo apt update in nato izrecno namesti različico izdaje (običajno je to prehod na nižjo različico), npr. sudo apt install openelp=0.9.3-1~trixie.

Omrežje in požarni zid

Odjemalci EchoLink se s proxyjem povežejo prek TCP na nastavljenih vratih Port (privzeto 8100). Sam proxy mora biti dosegljiv iz interneta na vratih UDP 5198 in 5199 (posreduj jih na usmerjevalniku, če je proxy za NAT) ter potrebuje odhodni dostop do vrat TCP 5200 in vrat UDP 5198/5199. Dostop do vrat proxyja dovoli le svojim odjemalcem, razen če upravljaš javni proxy.

Uporaba proxyja s SvxLink

V konfiguraciji modula EchoLink za SvxLink (/etc/svxlink/svxlink.d/ModuleEchoLink.conf) ga usmeri na proxy in znova zaženi SvxLink:

PROXY_SERVER=192.0.2.10    # naslov gostitelja OpenELP
PROXY_PORT=8100
PROXY_PASSWORD=your-password

Uradni odjemalec EchoLink za PC se nastavi na enak način v Setup → Connections → Proxy.

Uveljavitev sprememb konfiguracije

OpenELP prebere svojo konfiguracijo le ob zagonu. Po urejanju /etc/openelp/ELProxy.conf znova zaženi storitev (to prekine aktivne povezave odjemalcev):

sudo systemctl restart openelp.service

Lokalne spremembe v /etc/openelp/ELProxy.conf se pri nadgradnjah ohranijo (gre za konfiguracijsko datoteko dpkg). Ker vsebuje geslo proxyja, jo lahko bereta le root in skupina openelp, pod katero teče storitev.

Namestitev starejše različice

Nedavne različice ostanejo v bazenu (pool) na voljo še nekaj časa po zamenjavi (dnevne en teden, tedenske en mesec, mesečne eno leto — glej razdelek »Retention« (hramba) v UPSTREAM-SYNC.MD), zato je slabo dnevno gradnjo običajno mogoče povrniti. Paketi izdaj izvornega projekta (komponenta release) se nikoli ne odstranijo:

apt list -a openelp   # izpiše vse različice, ki so še v repozitoriju
sudo apt install openelp=0.9.4~dev+daily20261108.12.1.g0123456789ab-1~trixie
sudo apt-mark hold openelp   # neobvezno: prepreči, da bi ga "apt upgrade" znova posodobil
# sudo apt-mark unhold openelp   # pozneje, za nadaljevanje samodejnih posodobitev

Paketi

PaketVsebuje
openelpProxy demon openelpd in njegovo knjižnico, vzorčno konfiguracijo /etc/openelp/ELProxy.conf, storitev systemd (openelp.service, ni samodejno omogočena; teče kot neprivilegirani uporabnik openelp v peskovniku systemd) in stran priročnika man. Zgrajen s sistemsko knjižnico PCRE2, s priloženo implementacijo MD5 (brez odvisnosti od OpenSSL) in beleženjem prek sysloga. Razvojne glave niso vključene.

32-bitni sistemi: paketi armhf so zgrajeni za Raspbian (ARMv6+VFP), osnovo 32-bitnega Raspberry Pi OS, zato delujejo na vseh modelih Raspberry Pi, vključno s Pi 1, Zero in Zero W, namestijo pa se tudi na Debian armhf (oboje je preizkušeno). i386 (32-bitni osebni računalniki) se gradi le za Debian 12: Debian 13 ne podpira več namestitve sistemov i386. 32-bitni paketi imajo enake funkcije kot 64-bitni.
