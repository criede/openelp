APT-рэпазіторый OpenELP DB9CR

⚠ Гэтая старонка перакладзена аўтаматычна з дапамогай штучнага інтэлекту і можа ўтрымліваць памылкі. Вызначальнай з’яўляецца англійская версія. (English)

Пакеты OpenELP, проксі EchoLink з адкрытым зыходным кодам, для Raspberry Pi OS і Debian у двух кампанентах — выберы адзін:

  • main: штодзённыя зборкі для распрацоўкі з найсвяжэйшага зыходнага кода гэтага форка, а не стабільныя выпускі.
  • release: афіцыйныя выпускі OpenELP з upstream (0.9.3 і навейшыя), сабраныя з нязменнага зыходнага кода выпуску upstream з тымі ж параметрамі зборкі, што і штодзённыя пакеты. Кожны выпуск захоўваецца; apt upgrade пераходзіць на кожны новы выпуск upstream.

Падрабязнасці глядзі ў рэпазіторыі зыходнага кода.

Upstream і лакальныя змены

Гэта штодня сінхранізаваны форк cottsay/openelp, арыгінальнага праекта OpenELP, з лакальным пакаваннем (гэты APT-рэпазіторый) і, магчыма, далейшымі зменамі па-над ім. Каб у любы момант дакладна ўбачыць, чым форк адрозніваецца ад upstream, параўнай актуальны стан на GitHub: upstream main … main гэтага форка.

Хуткі старт

Выканай на мэтавай сістэме (патрэбныя кодавая назва і архітэктура вызначаюцца аўтаматычна):

# Імпарт адкрытага ключа подпісу
curl -fsSL https://criede.github.io/openelp/pubkey.gpg | \
  sudo gpg --dearmor -o /usr/share/keyrings/openelp-db9cr.gpg

# Даданне крыніцы рэпазіторыя. Выберы кампанент:
#   main     штодзённыя зборкі для распрацоўкі
#   release  афіцыйныя выпускі upstream (0.9.3 і навейшыя)
component=release
codename=$(sed -n 's/^VERSION_CODENAME=//p' /etc/os-release | tr -d '"')
arch=$(dpkg --print-architecture)
echo "deb [signed-by=/usr/share/keyrings/openelp-db9cr.gpg arch=${arch}] https://criede.github.io/openelp ${codename} ${component}" | \
  sudo tee /etc/apt/sources.list.d/openelp-db9cr.list

sudo apt update
sudo apt install openelp

# Абавязкова перад першым запускам: задай пароль (і пры жаданні
# порт, адрасы прывязкі, рэгістрацыю і фільтры пазыўных).
sudo editor /etc/openelp/ELProxy.conf

# Уключыць запуск проксі пры загрузцы сістэмы і запусціць яго зараз.
sudo systemctl enable --now openelp.service

# Праверыць стан службы і сачыць за яе журналам.
systemctl status openelp.service
journalctl -u openelp.service -f

Абавязкова: Проксі не запусціцца, пакуль Password у /etc/openelp/ELProxy.conf усё яшчэ мае значэнне notset. Выберы ўласны пароль; усталёўвай PUBLIC толькі калі хочаш запусціць публічны проксі (разам з унікальным RegistrationName).

Калі apt update паведамляе пра памылку 404 для гэтай крыніцы, для кодавай назвы тваёй сістэмы яшчэ няма зборак (глядзі табліцу ніжэй) — замест гэтага змяні кодавую назву ў /etc/apt/sources.list.d/openelp-db9cr.list на адну з падтрымліваемых. Пасля гэтага звычайная каманда sudo apt upgrade аўтаматычна атрымлівае новыя штодзённыя зборкі (main) або новыя выпускі upstream (release) і перазапускае працуючы проксі.

Не ўключай абодва кампаненты адначасова: apt заўсёды ўсталёўвае вышэйшую версію, а гэта звычайна штодзённая зборка. Каб перавесці існуючую ўсталёўку з main на release, змяні кампанент у /etc/apt/sources.list.d/openelp-db9cr.list, выканай sudo apt update, а потым яўна ўсталюйце версію выпуску (звычайна гэта паніжэнне версіі), напрыклад sudo apt install openelp=0.9.3-1~trixie.

Сетка і брандмаўэр

Кліенты EchoLink падключаюцца да проксі па TCP на наладжаны Port (па змаўчанні 8100). Сам проксі павінен быць даступны з Інтэрнэту па UDP-портах 5198 і 5199 (перанакіруй іх на маршрутызатары, калі проксі знаходзіцца за NAT) і мае патрэбу ў выходным доступе да TCP-порта 5200 і UDP-портаў 5198/5199. Дазваляй доступ да порта проксі толькі сваім кліентам, калі ты не запускаеш публічны проксі.

Выкарыстанне проксі з SvxLink

У канфігурацыі модуля EchoLink для SvxLink (/etc/svxlink/svxlink.d/ModuleEchoLink.conf) укажы проксі і перазапусці SvxLink:

PROXY_SERVER=192.0.2.10    # адрас хоста OpenELP
PROXY_PORT=8100
PROXY_PASSWORD=your-password

Афіцыйны кліент EchoLink для ПК наладжваецца гэтак жа у раздзеле Setup → Connections → Proxy.

Ужыванне змен канфігурацыі

OpenELP счытвае сваю канфігурацыю толькі пры запуску. Пасля рэдагавання /etc/openelp/ELProxy.conf перазапусці службу (пры гэтым актыўныя кліенцкія злучэнні разрываюцца):

sudo systemctl restart openelp.service

Лакальныя змены ў /etc/openelp/ELProxy.conf захоўваюцца пры абнаўленнях (гэта канфігурацыйны файл dpkg). Файл даступны для чытання толькі root, бо ён змяшчае пароль проксі.

Усталёўка старэйшай версіі

Нядаўнія версіі застаюцца даступнымі ў пуле (pool) яшчэ нейкі час пасля замены навейшымі (штодзённыя на працягу тыдня, штотыднёвыя на працягу месяца, штомесячныя на працягу года — глядзі раздзел «Retention» (захоўванне) у UPSTREAM-SYNC.MD), таму няўдалую штодзённую зборку звычайна можна адкаціць. Пакеты выпускаў upstream (кампанент release) ніколі не выдаляюцца:

apt list -a openelp   # паказвае ўсе версіі, якія яшчэ ёсць у рэпазіторыі
sudo apt install openelp=0.9.4~dev+daily20261108.12.1.g0123456789ab-1~trixie
sudo apt-mark hold openelp   # неабавязкова: не дае "apt upgrade" зноў яе абнавіць
# sudo apt-mark unhold openelp   # пазней, каб аднавіць аўтаматычныя абнаўленні
