OpenELP DB9CR APT repository

Packages of OpenELP, the Open Source EchoLink Proxy, for Raspberry Pi OS and Debian, in two components — pick one:

  • main: daily development builds from the latest source of this fork, not stable releases.
  • release: the official upstream OpenELP releases (0.9.3 and newer), built from the unmodified upstream release source with the same build settings as the daily packages. Every release is kept; apt upgrade moves to each new upstream release.

See the source repository for details.

Upstream & local changes

This is a daily-synced fork of cottsay/openelp, the original OpenELP project, with local packaging (this APT repository) and possibly further changes layered on top. To see exactly what is different from upstream at any point in time, compare live on GitHub: upstream main … this fork's main.

Security: the main packages drop packets from the EchoLink network that would trigger known SvxLink vulnerabilities before they reach a SvxLink node using this proxy: malformed NDATA info/chat packets (CVE-2026-73152 / GHSA-2m63-p9h9-p5rf: crash, memory disclosure) and RTCP SDES packets with a callsign containing invalid characters or more than 32 characters (GHSA-6w9x-486p-ggrj: TCL command injection, buffer overflows). They also limit the time a client may take to log in. This is a stop-gap, not a replacement for updating SvxLink to 26.05.2 or newer. The release packages contain unmodified upstream source without these changes; both run the proxy in a systemd sandbox.

Quickstart

Run on the target system (detects the right codename/architecture automatically):

# Import the public signing key
curl -fsSL https://criede.github.io/openelp/pubkey.gpg | \
  sudo gpg --dearmor -o /usr/share/keyrings/openelp-db9cr.gpg

# Add the repository source. Choose the component:
#   main     daily development builds
#   release  official upstream releases (0.9.3 and newer)
component=release
codename=$(sed -n 's/^VERSION_CODENAME=//p' /etc/os-release | tr -d '"')
arch=$(dpkg --print-architecture)
echo "deb [signed-by=/usr/share/keyrings/openelp-db9cr.gpg arch=${arch}] https://criede.github.io/openelp ${codename} ${component}" | \
  sudo tee /etc/apt/sources.list.d/openelp-db9cr.list

sudo apt update
sudo apt install openelp

# Mandatory before the first start: set a password (and optionally the
# port, bind addresses, registration and callsign filters).
sudo editor /etc/openelp/ELProxy.conf

# Enable the proxy at boot and start it now.
sudo systemctl enable --now openelp.service

# Check service state and follow its log.
systemctl status openelp.service
journalctl -u openelp.service -f

Required: The proxy refuses to start while Password in /etc/openelp/ELProxy.conf is still notset. Choose a password of your own; set it to PUBLIC only if you want to run a public proxy (together with a unique RegistrationName).

If apt update reports a 404 for this source, your system's codename isn't built yet (see the table below) — edit the codename in /etc/apt/sources.list.d/openelp-db9cr.list to one of the supported ones instead. Afterwards, a regular sudo apt upgrade picks up new daily builds (main) or new upstream releases (release) automatically and restarts a running proxy.

Do not enable both components at once: apt always installs whichever version is higher, which is usually a daily build. To switch an existing installation from main to release, change the component in /etc/apt/sources.list.d/openelp-db9cr.list, run sudo apt update, then install the release version explicitly (usually a downgrade), e.g. sudo apt install openelp=0.9.3-2~trixie.

Network and firewall

EchoLink clients connect to the proxy over TCP on the configured Port (default 8100). The proxy itself must be reachable from the Internet on UDP ports 5198 and 5199 (forward them on your router if the proxy is behind NAT) and needs outgoing access to TCP port 5200 and UDP ports 5198/5199. Allow only your own clients to reach the proxy port unless you run a public proxy.

Using the proxy with SvxLink

In SvxLink's EchoLink module configuration (/etc/svxlink/svxlink.d/ModuleEchoLink.conf), point it to the proxy and restart SvxLink:

PROXY_SERVER=192.0.2.10    # address of the OpenELP host
PROXY_PORT=8100
PROXY_PASSWORD=your-password

The official EchoLink PC client is configured the same way under Setup → Connections → Proxy.

Applying configuration changes

OpenELP reads its configuration only at startup. After editing /etc/openelp/ELProxy.conf, restart the service (this drops active client connections):

sudo systemctl restart openelp.service

Local changes to /etc/openelp/ELProxy.conf are kept on upgrades (it is a dpkg configuration file). Since it contains the proxy password, the file is readable only by root and the openelp group the service runs as.

Installing an older version

Recent versions stay available in the pool for a while after being superseded (daily for a week, weekly for a month, monthly for a year — see "Retention" in UPSTREAM-SYNC.MD), so a bad daily build can usually be rolled back. Upstream release packages (release component) are never removed:

apt list -a openelp   # lists every version still in the repository
sudo apt install openelp=0.9.4~dev+daily20261108.12.1.g0123456789ab-1~trixie
sudo apt-mark hold openelp   # optional: stop "apt upgrade" pulling it forward again
# sudo apt-mark unhold openelp   # later, to resume automatic updates

Packages

PackageContains
openelpThe openelpd proxy daemon and its library, the sample configuration /etc/openelp/ELProxy.conf, a systemd service (openelp.service, not enabled automatically; runs as the unprivileged user openelp in a systemd sandbox) and the manual page. Built against the system PCRE2 library, with the bundled MD5 implementation (no OpenSSL dependency) and syslog logging. Development headers are not included.

32-bit systems: armhf packages are built against Raspbian (ARMv6+VFP), the base of 32-bit Raspberry Pi OS, so they run on every Raspberry Pi model including the Pi 1, Zero and Zero W, and also install on Debian armhf (both are tested). i386 (32-bit PCs) is built for Debian 12 only: Debian 13 no longer supports installing i386 systems. The 32-bit packages contain the same features as the 64-bit ones.
