Αποθετήριο APT του OpenELP DB9CR

⚠ Αυτή η σελίδα μεταφράστηκε αυτόματα με τεχνητή νοημοσύνη και ενδέχεται να περιέχει σφάλματα. Ισχύει η αγγλική έκδοση. (English)

Πακέτα του OpenELP, του EchoLink Proxy ανοιχτού κώδικα, για Raspberry Pi OS και Debian, σε δύο συνιστώσες (components) — επίλεξε μία:

  • main: καθημερινές εκδόσεις ανάπτυξης (daily builds) από τον πιο πρόσφατο πηγαίο κώδικα αυτού του fork, όχι σταθερές εκδόσεις.
  • release: οι επίσημες εκδόσεις του upstream OpenELP (0.9.3 και νεότερες), μεταγλωττισμένες από τον αμετάβλητο πηγαίο κώδικα της έκδοσης upstream με τις ίδιες ρυθμίσεις μεταγλώττισης όπως τα καθημερινά πακέτα. Κάθε έκδοση διατηρείται· το apt upgrade μεταβαίνει σε κάθε νέα έκδοση upstream.

Για λεπτομέρειες δες το αποθετήριο πηγαίου κώδικα.

Upstream και τοπικές αλλαγές

Αυτό είναι ένα fork που συγχρονίζεται καθημερινά με το cottsay/openelp, το αρχικό έργο OpenELP, με τοπική πακετοποίηση (αυτό το αποθετήριο APT) και ενδεχομένως περαιτέρω αλλαγές από πάνω. Για να δεις ακριβώς τι διαφέρει από το upstream σε οποιαδήποτε χρονική στιγμή, κάνε ζωντανή σύγκριση στο GitHub: upstream main … main αυτού του fork.

Γρήγορη εκκίνηση

Εκτέλεσε στο σύστημα-στόχο (η σωστή κωδική ονομασία/αρχιτεκτονική εντοπίζεται αυτόματα):

# Εισαγωγή του δημόσιου κλειδιού υπογραφής
curl -fsSL https://criede.github.io/openelp/pubkey.gpg | \
  sudo gpg --dearmor -o /usr/share/keyrings/openelp-db9cr.gpg

# Προσθήκη της πηγής του αποθετηρίου. Επίλεξε τη συνιστώσα (component):
#   main     καθημερινές εκδόσεις ανάπτυξης
#   release  επίσημες εκδόσεις upstream (0.9.3 και νεότερες)
component=release
codename=$(sed -n 's/^VERSION_CODENAME=//p' /etc/os-release | tr -d '"')
arch=$(dpkg --print-architecture)
echo "deb [signed-by=/usr/share/keyrings/openelp-db9cr.gpg arch=${arch}] https://criede.github.io/openelp ${codename} ${component}" | \
  sudo tee /etc/apt/sources.list.d/openelp-db9cr.list

sudo apt update
sudo apt install openelp

# Υποχρεωτικό πριν από την πρώτη εκκίνηση: όρισε κωδικό πρόσβασης (και προαιρετικά
# τη θύρα, τις διευθύνσεις δέσμευσης, την καταχώριση και τα φίλτρα διακριτικών κλήσης).
sudo editor /etc/openelp/ELProxy.conf

# Ενεργοποίηση του proxy κατά την εκκίνηση του συστήματος και άμεση εκκίνησή του.
sudo systemctl enable --now openelp.service

# Έλεγχος της κατάστασης της υπηρεσίας και παρακολούθηση του αρχείου καταγραφής της.
systemctl status openelp.service
journalctl -u openelp.service -f

Απαιτείται: Το proxy αρνείται να ξεκινήσει όσο το Password στο /etc/openelp/ELProxy.conf είναι ακόμη notset. Επίλεξε δικό σου κωδικό πρόσβασης· όρισέ τον σε PUBLIC μόνο αν θέλεις να λειτουργήσεις δημόσιο proxy (μαζί με ένα μοναδικό RegistrationName).

Αν το apt update αναφέρει σφάλμα 404 για αυτή την πηγή, η κωδική ονομασία του συστήματός σου δεν έχει ακόμη μεταγλωττιστεί (δες τον πίνακα παρακάτω) — αντί γι' αυτό άλλαξε την κωδική ονομασία στο /etc/apt/sources.list.d/openelp-db9cr.list σε μία από τις υποστηριζόμενες. Στη συνέχεια, ένα κανονικό sudo apt upgrade λαμβάνει αυτόματα νέες καθημερινές εκδόσεις (main) ή νέες εκδόσεις upstream (release) και επανεκκινεί ένα proxy που εκτελείται.

Μην ενεργοποιείς και τις δύο συνιστώσες ταυτόχρονα: το apt εγκαθιστά πάντα την υψηλότερη έκδοση, που συνήθως είναι μια καθημερινή έκδοση. Για να αλλάξεις μια υπάρχουσα εγκατάσταση από main σε release, άλλαξε τη συνιστώσα στο /etc/apt/sources.list.d/openelp-db9cr.list, εκτέλεσε sudo apt update και μετά εγκατάστησε ρητά την έκδοση release (συνήθως πρόκειται για υποβάθμιση), π.χ. sudo apt install openelp=0.9.3-1~trixie.

Δίκτυο και τείχος προστασίας

Οι πελάτες EchoLink συνδέονται στο proxy μέσω TCP στη ρυθμισμένη Port (προεπιλογή 8100). Το ίδιο το proxy πρέπει να είναι προσβάσιμο από το Διαδίκτυο στις θύρες UDP 5198 και 5199 (προώθησέ τις στον δρομολογητή σου αν το proxy βρίσκεται πίσω από NAT) και χρειάζεται εξερχόμενη πρόσβαση στη θύρα TCP 5200 και στις θύρες UDP 5198/5199. Επίτρεψε μόνο στους δικούς σου πελάτες να φτάνουν στη θύρα του proxy, εκτός αν λειτουργείς δημόσιο proxy.

Χρήση του proxy με το SvxLink

Στις ρυθμίσεις της μονάδας EchoLink του SvxLink (/etc/svxlink/svxlink.d/ModuleEchoLink.conf), κατεύθυνέ την στο proxy και επανεκκίνησε το SvxLink:

PROXY_SERVER=192.0.2.10    # διεύθυνση του κεντρικού υπολογιστή OpenELP
PROXY_PORT=8100
PROXY_PASSWORD=your-password

Ο επίσημος πελάτης EchoLink για PC ρυθμίζεται με τον ίδιο τρόπο στο Setup → Connections → Proxy.

Εφαρμογή αλλαγών στις ρυθμίσεις

Το OpenELP διαβάζει τις ρυθμίσεις του μόνο κατά την εκκίνηση. Μετά την επεξεργασία του /etc/openelp/ELProxy.conf, επανεκκίνησε την υπηρεσία (αυτό διακόπτει τις ενεργές συνδέσεις πελατών):

sudo systemctl restart openelp.service

Οι τοπικές αλλαγές στο /etc/openelp/ELProxy.conf διατηρούνται κατά τις αναβαθμίσεις (είναι αρχείο ρυθμίσεων του dpkg). Το αρχείο είναι αναγνώσιμο μόνο από τον root, καθώς περιέχει τον κωδικό πρόσβασης του proxy.

Εγκατάσταση παλαιότερης έκδοσης

Οι πρόσφατες εκδόσεις παραμένουν διαθέσιμες στο pool για κάποιο διάστημα αφού αντικατασταθούν (οι καθημερινές για μία εβδομάδα, οι εβδομαδιαίες για έναν μήνα, οι μηνιαίες για έναν χρόνο — δες την ενότητα «Retention» (διατήρηση) στο UPSTREAM-SYNC.MD), οπότε μια προβληματική καθημερινή έκδοση μπορεί συνήθως να αναιρεθεί. Τα πακέτα εκδόσεων upstream (συνιστώσα release) δεν αφαιρούνται ποτέ:

apt list -a openelp   # εμφανίζει κάθε έκδοση που υπάρχει ακόμη στο αποθετήριο
sudo apt install openelp=0.9.4~dev+daily20261108.12.1.g0123456789ab-1~trixie
sudo apt-mark hold openelp   # προαιρετικά: εμποδίζει το "apt upgrade" να την αναβαθμίσει ξανά
# sudo apt-mark unhold openelp   # αργότερα, για να συνεχιστούν οι αυτόματες ενημερώσεις

Πακέτα

ΠακέτοΠεριεχόμενα
openelpΟ δαίμονας proxy openelpd και η βιβλιοθήκη του, το δείγμα ρυθμίσεων /etc/openelp/ELProxy.conf, μια υπηρεσία systemd (openelp.service, δεν ενεργοποιείται αυτόματα) και η σελίδα εγχειριδίου (man). Μεταγλωττισμένο με τη βιβλιοθήκη PCRE2 του συστήματος, με την ενσωματωμένη υλοποίηση MD5 (χωρίς εξάρτηση από το OpenSSL) και καταγραφή μέσω syslog. Δεν περιλαμβάνονται αρχεία κεφαλίδων ανάπτυξης.

Υποστηριζόμενα συστήματα

Κωδική ονομασίαΑντιστοιχεί σεΑρχιτεκτονικές: main (καθημερινές)Αρχιτεκτονικές: release
bookwormDebian 12, Raspberry Pi OS Bookworm (64/32 bit)amd64 arm64 armhf i386armhf
trixieDebian 13, Raspberry Pi OS Trixie (64/32 bit)amd64 arm64 armhfarmhf

Συστήματα 32 bit: τα πακέτα armhf μεταγλωττίζονται για Raspbian (ARMv6+VFP), τη βάση του Raspberry Pi OS 32 bit, ώστε να λειτουργούν σε κάθε μοντέλο Raspberry Pi, συμπεριλαμβανομένων των Pi 1, Zero και Zero W, και εγκαθίστανται επίσης σε Debian armhf (και τα δύο έχουν δοκιμαστεί). Το i386 (PC 32 bit) μεταγλωττίζεται μόνο για Debian 12: το Debian 13 δεν υποστηρίζει πλέον την εγκατάσταση συστημάτων i386. Τα πακέτα 32 bit περιέχουν τις ίδιες λειτουργίες με τα πακέτα 64 bit.
